# Gemini に質問する

Gemini CLI を非対話モードで実行して回答を得る。

## 使い方

質問は **heredoc で stdin に渡す**。`-p` はヘッドレスモードを有効にするフラグで、その内容は stdin の入力の**後ろに追記**される。

```bash
gemini --skip-trust --approval-mode plan -p "上記に回答してください。" <<'EOF'
<質問内容>
EOF
```

- 引数（$ARGUMENTS）があればそれをそのまま質問として渡す。なければ会話の文脈から質問を組み立てる。
- ファイル内容を読ませたい場合はパイプで渡す（ファイル内容にシェル展開は起きないので安全）:

```bash
cat path/to/file | gemini --skip-trust --approval-mode plan -p "<このコードについての質問>"
```

- モデルを指定したい場合は `-m` を使う（例: `-m gemini-2.5-pro`）。指定がなければデフォルトのまま。

> **`-p "..."` に質問を直接埋め込んではいけない。** コード関連の質問にはバッククォート・`$(...)`・`"` が高確率で含まれ、ダブルクォート内ではシェルがそれらを**実行してしまう**。実測で `` `echo BROKEN` `` と `$(echo INJECTED)` が実行され、その出力に置換された。`<<'EOF'`（EOF をクォート）ならシェル展開が一切起きず原文がそのまま届く。

## 注意

- 認証は環境変数 `GEMINI_API_KEY` で行われる（zshrc で設定済み）。
- `--approval-mode plan` は read-only モード。質問するだけのこのスキルではツール実行が不要なので常に付ける。`--skip-trust` はヘッドレス実行時に対話的な信頼確認で止まらないために必要。
- 起動時に `[STARTUP] Phase 'cleanup_ops' ...` のような警告が stderr に出ることがあるが、回答には影響しないので無視してよい。
- 実行後は Gemini の回答をそのまま貼るのではなく、要点をまとめてユーザーに伝える。
