# 危険な条項と修正文例

契約書に出てくる**不利な条項の実物**と、そのまま差し込める修正案。**受託者(乙)の視点を主軸**に、委託者(甲)側の見え方も併記する。

> **使い方:** レビュー中に該当条項を見つけたら、ここの「何が起きるか」を読み、修正案を成果物にコピーして案件の実情に合わせて数字を埋める。**丸写ししない** — 上限額・期間・地名は必ず案件に合わせる。
>
> **前提:** 準拠法は日本法。表記は `甲 = 委託者(発注者)` / `乙 = 受託者(開発側)`。契約書によって甲乙が逆のことがあるので、**必ず冒頭の定義を確認してから**当てること。
>
> **ここに書いた法令はすべて一次情報で確認済み**(→ [law-notes.md](law-notes.md))。ただし**条文の当てはめは弁護士の領分**。「◯条により無効」と書かず、「◯条があるので弁護士に確認」と書く。

## 1. 損害賠償の上限がない

### 危険な原文の例

```
第◯条(損害賠償)
1. 乙は、本契約に違反し、又は本業務の遂行に関して甲に損害を与えたときは、
   甲に生じた一切の損害(逸失利益、第三者からの請求に基づく損害を含む)を
   賠償しなければならない。
```

### 何が起きるか

**報酬 100 万円の案件で、賠償が 1 億円になり得る。** 上限を書かないと、賠償額は民法 416 条の枠(通常損害 + 予見すべきであった特別損害)で決まり、契約で頭打ちにならない。

具体的なシナリオ:

- 納品したバッチに不具合 → 甲の EC サイトが 3 日停止 → **その 3 日分の売上を「逸失利益」として請求される**。報酬額とは何の関係もない金額になる
- 甲がエンドクライアントに支払った違約金を、そのまま乙に転嫁する(「第三者からの請求に基づく損害」がこれを可能にする)
- 障害調査・データ復旧を甲が外部ベンダーに発注 → その費用も「損害」として乗る

**「一切の損害」は事実上の無限責任**。個人・小規模法人にとっては事業継続そのものが飛ぶ条項で、優先度は常に最上位。

> **上限が無いと保険にも乗らない。** 賠償責任保険を検討する場合も、契約上の責任範囲が青天井だと補償の外側が残る。上限を入れることは保険設計の前提でもある。

### 修正案

```
第◯条(損害賠償)
1. 甲及び乙は、本契約に関し、相手方の責めに帰すべき事由により損害を被った
   ときは、相手方に対しその損害の賠償を請求することができる。
2. 前項に基づく賠償の範囲は、通常生ずべき直接の損害に限るものとし、
   逸失利益、事業機会の喪失、データの喪失、第三者からの請求その他の
   間接損害、特別損害及び結果的損害を含まないものとする。
3. 本契約に基づく一方当事者の相手方に対する損害賠償の累計額は、
   事由の如何を問わず、本契約に基づき甲が乙に対して支払った
   (又は支払うべき)委託料の総額を上限とする。
4. 前二項は、損害を与えた当事者に故意又は重過失がある場合には適用しない。
```

**押さえどころ:**

- **2 項(範囲の限定)と 3 項(金額の上限)は別物。** 片方だけでは効かない。逸失利益を除外しても上限が無ければ直接損害だけで報酬を超え得るし、上限だけ入れても除外条項が無いと交渉で争点が残る
- **「甲及び乙は」と双方向にする**のがコツ。片務的な免責より圧倒的に通りやすい
- 4 項(故意・重過失の除外)は入れておく。これを書かないと「上限条項ごと無効」と争われる余地が広がる。**先に自分から出す**と交渉が早い
- 継続契約なら「委託料の総額」ではなく**「損害発生時点から遡って 12 か月間に支払われた委託料」**にする。長期契約で総額が膨らむのを避ける

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **逸失利益・間接損害の除外**(2 項) | 金額上限より通りやすい。かつ実害としてはこちらの方が大きいことが多い |
| 2 | **金額上限**(3 項) | 「報酬額」で押す。飲まれなければ「報酬額の 2 倍」「◯◯万円」など具体額で妥協 |
| 3 | 責任期間の限定 | 「引渡し後 1 年以内に請求されたものに限る」を足せると強い |

**全部断られたときの最低ライン:** 少なくとも「**乙の故意又は重過失による場合を除き、逸失利益を含まない**」の一文を入れる。ここすら通らない相手は、条件全体を見直す判断材料になる。

**委託側(甲)なら:** 上限を報酬額にすると、大規模障害時に回収不能になる。**重要なシステムほど上限を引き上げるか、上限の例外(情報漏えい・知財侵害・故意重過失)を列挙する**。実務では「原則は報酬額上限、ただし情報漏えいと第三者知財侵害は上限の対象外」という設計が落としどころになりやすい。

## 2. 契約不適合責任の期間が長すぎる / 無期限

### 危険な原文の例

```
第◯条(契約不適合責任)
1. 乙は、本件成果物に契約の内容に適合しない点が発見された場合、
   期間の定めなく、無償で修補、代替物の納入又は不足分の納入を行う。
2. 前項は、甲が乙に対して損害賠償を請求することを妨げない。
```

あるいは「**検収後 5 年間**」「**甲が不適合を発見したときから 1 年間**」といった書き方。

### 何が起きるか

**納品から何年経っても無償改修に呼び戻される。** 民法の請負の契約不適合責任は、注文者が**不適合を知った時から 1 年以内に通知**すれば足りる建て付け(民法 637 条 1 項)で、この期間は契約で変更できる**任意規定**。だから契約書側で無期限に伸ばされる。

具体的なシナリオ:

- 3 年前に納品したシステムで不具合が出る → 当時の開発メンバーはもういない → **ソースを読み直すところから無償でやる羽目になる**
- 「甲が発見したときから 1 年」は**起算点が甲に握られている**ため、実質的に無期限と同じ。10 年後に発見されればそこから 1 年始まる
- OS・ライブラリのバージョンアップで動かなくなったものまで「契約不適合」として持ち込まれる(**期間だけでなく範囲の問題も同時に起きる**)

> **無期限だから安心、とは限らない。** 通知期間を無期限にしても、損害賠償請求権そのものは民法 166 条の消滅時効(権利行使できると知った時から 5 年 / 行使できる時から 10 年)に服する。だが**「時効まで争う」は勝ち筋ではない**。契約側で期間を切るのが実務。

### 修正案

```
第◯条(契約不適合責任)
1. 甲は、本件成果物が種類、品質又は数量に関して本契約の内容に
   適合しないことを発見した場合、検収完了日から 6 か月以内に限り、
   乙に対して当該不適合の内容を書面により通知することができる。
2. 乙は、前項の通知を受けた場合、相当の期間内に、無償にて修補を行う。
   修補に過分の費用を要する場合その他修補が相当でない場合には、
   甲乙協議のうえ代金の減額その他の措置を定めるものとする。
3. 甲が第 1 項の期間内に通知を行わなかった場合、乙は当該不適合に関する
   一切の責任を負わない。
4. 次の各号に該当する事由に起因する不適合については、
   乙は本条の責任を負わない。
   (1) 甲が提供した資料、仕様、指図又は素材に起因するもの
   (2) 甲又は第三者が本件成果物を改変したことに起因するもの
   (3) 本契約において前提とした稼働環境(OS、ミドルウェア、
       外部 API 等)の変更又は提供終了に起因するもの
   (4) 甲が乙の指示した運用方法に従わなかったことに起因するもの
```

**押さえどころ:**

- **起算点を「検収完了日」という客観日に固定する**。「発見したときから」は絶対に避ける。ここが最重要で、期間の長さより効く
- **4 項(免責事由)が本体**。期間だけ短くしても、「甲の指図どおりに作ったものの不具合」まで背負うなら意味が薄い。民法 636 条は注文者の供した材料・指図による不適合について請負人の責任を制限しているが、**契約に書いておく方が争いにならない**
- 3 号(稼働環境の変更)は**ソフトウェア特有**で、抜けやすい。入れておくと数年後に効く
- 「無償で修補」だけでなく **2 項の逃げ道(修補が相当でない場合)** を作る。作り直しが実質不可能なものを無限に押し付けられない

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **起算点を検収日にする** | 期間の長短より重要。「発見時から」だけは絶対に外す |
| 2 | **免責事由(4 項)** | 期間より通りやすい。相手も「自分の指図のせい」までは押しにくい |
| 3 | 期間を 6 か月〜1 年に | 1 年は民法の建て付けに沿うので説得しやすい。3 か月まで詰められれば上出来 |
| 4 | 責任の上限を賠償条項に紐付け | 「本条の責任は第◯条(損害賠償)の上限に服する」の一文を足す |

**最低ライン:** 期間が動かせないなら、せめて **4 項の免責事由**と「本条の責任は第◯条の上限に服する」の一文を取る。無期限 × 無限額の組み合わせだけは避ける。

**委託側(甲)なら:** 6 か月は短すぎる場合がある。**年 1 回しか動かないバッチ処理**(年次決算処理など)は、1 年見ないと不具合が出ない。「検収日から 1 年」または「本件システムの初回の年次処理完了後 3 か月」といった業務サイクルに合わせた設計を検討する。

## 3. みなし検収がない

### 危険な原文の例

```
第◯条(検収)
1. 乙は、本件成果物を甲に納入する。
2. 甲は、納入された本件成果物を検査し、合格と認めたときは
   乙に対して検収完了通知書を交付する。
3. 委託料は、検収完了後、甲の定める支払条件に従い支払う。
```

**問題は書いてあることではなく、書いていないこと。** 検査の期限も、期限を過ぎたときの扱いも無い。

### 何が起きるか

**検収が永遠に終わらず、報酬が発生しない。** 支払が「検収完了後」に紐付いているので、甲が検収通知書を出さない限り、乙は納品を終えているのに請求権が立たない。

具体的なシナリオ:

- 納品 → 甲の担当者が多忙 → 2 か月放置 → **催促すると「まだ確認できていません」で終わる**。請求書すら出せない
- 甲の社内稟議・予算タイミングの都合で、検収を意図的に翌期に送られる
- 追加要望を出し続けることで検収を完了させない(→ [4](#4-検収基準が主観的) と [16](#16-仕様変更やり直しが無償で無限に発生する) が同時に発動する)

> **これは「不利な条項がある」のではなく「有利な条項が無い」パターン。** チェックリストで**不在**を拾わないと丸ごと見落とす。契約書を読んで違和感が無いのに危険、という典型。

### 修正案

```
第◯条(検収)
1. 乙は、本件成果物を甲に納入する。
2. 甲は、納入日から 10 営業日以内(以下「検査期間」という。)に、
   別紙に定める検収基準に従って検査を行い、その結果を書面(電子メールを
   含む。以下同じ。)により乙に通知する。
3. 甲が検査期間内に前項の通知を行わない場合、当該検査期間の満了をもって
   検収に合格したものとみなす。
4. 甲が不合格と判定する場合、その理由及び検収基準のいずれに
   適合しないかを具体的に示して通知しなければならない。
   当該通知に理由の記載がない場合、第 3 項を準用する。
5. 乙は、前項の通知を受けた場合、甲乙協議のうえ定める期間内に
   修正のうえ再納入し、再納入後は第 2 項から第 4 項までを準用する。
   ただし、再検査の対象は第 4 項により通知された不適合部分に限る。
```

**押さえどころ:**

- **3 項(みなし検収)がこの条文の主役。** 検査期間を書いても、期限徒過時の効果を書かないと放置に対して無力
- **4 項後段(理由の無い不合格はみなし合格)** を入れる。これが無いと「不合格です」の一言で期限をリセットされ続ける
- **5 項ただし書(再検査は指摘部分に限る)** で、無限ループを止める。これが無いと再納入のたびに全体を検査し直され、新しい指摘が生える
- 「10 営業日」は案件規模で調整。小規模なら 5 営業日、大規模システムなら 20 営業日 + 段階検収

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **検査期間の明記**(2 項) | ここが無いと他が全部効かない。期間の長さは譲ってよい |
| 2 | **みなし検収**(3 項) | 「検査を促す規定であって、瑕疵の免責ではない」と説明すると通りやすい |
| 3 | 不合格理由の具体化(4 項) | 通りやすい。「手戻りを減らすため」という説明で押す |
| 4 | 再検査範囲の限定(5 項) | 通れば強い |

**みなし検収が絶対に飲まれないとき:** 甲が「検収しないと支払えない」構造そのものを外しにいく。

```
第◯条(委託料の支払)
甲は、納入日から 10 営業日以内に検収を完了するものとし、
当該期間内に検収が完了しない場合であっても、納入日の属する月の
末日を検収完了日とみなして委託料を支払う。
```

**支払だけでも切り離せば実害の大半は消える。** 検収の効果(契約不適合責任の起算など)は残しつつ、資金繰りへの打撃を避ける現実的な線。

**委託側(甲)なら:** みなし検収を入れる代わりに、**検査期間を十分に取る**(20 営業日など)ことと、**納入の要件を明確にする**(「必要な成果物一式とテスト結果報告書が揃った時点をもって納入とする」)ことで守る。一式揃っていないものを「納入」と主張されてみなし検収が走るのが最悪パターン。

## 4. 検収基準が主観的

### 危険な原文の例

```
第◯条(検収)
甲は、本件成果物が甲の求める品質及び水準を満たしていると
判断した場合に、検収完了とする。
```

同種の表現:「甲が満足するまで」「甲の指定する水準に達するまで」「実用に耐えると甲が認めたとき」「甲の承認を得るまで」。

### 何が起きるか

**完成の定義が相手の主観に握られ、いつまでも完成しない。** 請負は仕事の完成に対して報酬が発生する契約類型(民法 632 条)なので、**「完成」の判定基準が相手の内心なら、報酬請求権の発生条件も相手が握る**ことになる。

具体的なシナリオ:

- 仕様書どおりに実装 → 「思っていたのと違う」で不合格 → **仕様書に書いていない要望が「品質」の名で追加される**
- 担当者が交代 → 新担当が「自分の求める水準」を新たに主張 → やり直し
- 争いになったとき、「甲の求める品質」を客観的に立証できないため、**乙が完成を証明できない**

> **主観基準は [3](#3-みなし検収がない)(みなし検収なし)と [16](#16-仕様変更やり直しが無償で無限に発生する)(無償やり直し)と組み合わさると致命的。** 3 つ揃っている契約は、報酬の発生自体が相手の善意頼みになる。優先度を上げる。

### 修正案

```
第◯条(検収基準)
1. 本件成果物の検収は、別紙「検収基準書」に定める項目及び
   合否判定基準に従って行う。
2. 甲は、検収基準書に定める基準に適合しないことを理由とする場合に限り、
   不合格の判定を行うことができる。
3. 検収基準書に定めのない事項に関する甲の要望については、
   第◯条(仕様変更)に定める手続によるものとし、
   検収の合否判定の対象としない。
4. 検収基準書は、本契約締結後 ◯ 日以内に甲乙協議のうえ定め、
   書面により確定する。確定するまでの間は、要件定義書に記載された
   機能要件を充足することをもって検収基準とする。
```

**押さえどころ:**

- **2 項(基準以外を不合格理由にできない)がなければ、別紙を作った意味が半分になる。** 基準書を添付しただけでは「基準は満たしているが品質が低い」と言われる余地が残る
- **3 項(基準外の要望は仕様変更手続へ)** が、追加要望を有償の変更管理に流す導線。これが無いと基準書外の要望が「検収の一環」として無償で入ってくる
- **4 項(基準書の後決めと暫定基準)** は実務的な逃げ道。契約時点で検収基準書を完成させられない案件は多い。**「後で決める」だけ書いて期限と暫定基準を書かないと、永久に決まらない**
- 「甲の承認を得るまで」のような文言は、**削除ではなく置換**で対応する。承認プロセス自体は残していい。承認の判断基準を客観化するのが目的

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **検収基準書への紐付け**(1 項) | 「認識齟齬を防ぐため」で通しやすい。相手にもメリットがある |
| 2 | **基準外の要望は仕様変更へ**(3 項) | 追加報酬の根拠にもなる。ここが実利 |
| 3 | 基準外を不合格理由にできない(2 項) | やや強い要求。押せれば取る |

**最低ライン:** 契約書の文言が変えられなくても、**検収基準を別文書(仕様書・要件定義書・議事録)で合意し、記録に残す**。契約書に「甲が満足するまで」と書いてあっても、事実上の合意基準があれば交渉の拠り所になる。**「契約書は直せないので何もしない」が最悪の対応。**

**委託側(甲)なら:** 基準書に落とすと、基準書に書き漏らした要件が請求できなくなる。**非機能要件(性能・可用性・セキュリティ)を書き漏らさない**こと。「レスポンス 1 秒以内」「同時接続 100 人」など、数値で書いていないものは検収で主張できないと考えて臨む。

## 5. 著作権の全部譲渡 + 著作者人格権不行使

### 危険な原文の例

```
第◯条(知的財産権)
1. 本業務の遂行により生じた一切の成果物に関する著作権
   (著作権法第 27 条及び第 28 条の権利を含む。)その他一切の
   知的財産権は、その発生と同時に甲に帰属する。
2. 乙は、甲及び甲の指定する第三者に対し、著作者人格権を行使しない。
3. 乙は、本件成果物及びその一部を、第三者に対して提供し、
   又は自ら使用してはならない。
```

### 何が起きるか

**この 3 項がセットになると、自分が書いたコードを次の案件で使えなくなる。**

1 項だけなら「納品物の権利を渡す」という普通の条項で、受託開発では珍しくない。**問題は「一切の成果物」の射程と、3 項の再利用禁止。**

具体的なシナリオ:

- 案件のために書いた**汎用のユーティリティ関数・認証まわりの共通処理**まで甲に帰属する → 次の案件で同じコードを書いたら、契約違反 or 著作権侵害を主張され得る
- **契約前から持っていた自社ライブラリ**を組み込んで納品 → 「本業務の遂行により生じた成果物」に含まれると解釈され、自社の資産を失う
- 3 項により、**同種のサービスを自分で作ることもできなくなる**(実質的な競業避止として機能する)
- OSS を組み込んでいた場合、**そもそも乙が譲渡できない権利を譲渡すると約束している**ことになり、後で矛盾が露見する

法制度としての要点(いずれも一次情報で確認済 → [law-notes.md](law-notes.md)):

- **著作者人格権は譲渡できない**(著作権法 59 条)。だから実務では 2 項の「不行使特約」が使われる。「著作者人格権を譲渡する」と書いてある契約書は、その時点で**作成者が条文を確認していない**サイン。他の条項も疑ってかかる
- **27 条・28 条の特掲**(著作権法 61 条 2 項) — 譲渡契約でこの 2 条を明示していないと、譲渡人に留保されたと推定される。**甲側が入れてくるのは正当**であり、ここを削れという交渉は筋が悪い(削っても甲が改修できず、結局困るのは双方)
- **アルゴリズム・プログラム言語・規約は著作権法の保護対象外**(著作権法 10 条 3 項)。つまり**「頭の中の設計手法」は譲渡の対象にならない**。この事実は交渉の材料になる — 争点は「表現(コード)」に絞られる

> **狙うのは「譲渡を止めること」ではなく「留保の範囲を切り出すこと」。** 納品物の著作権を渡すのは受託開発として自然。全面拒否は交渉として通らないうえ、関係も悪くなる。**汎用部分の留保**に集中する。

### 修正案

```
第◯条(知的財産権)
1. 本件成果物に関する著作権(著作権法第 27 条及び第 28 条の権利を含む。)
   は、甲が乙に対して委託料を完済した時をもって、乙から甲に移転する。
2. 前項の定めにかかわらず、次の各号に掲げるもの(以下「乙既存資産」と
   いう。)に関する権利は、乙(又は当該権利の正当な権利者)に留保される。
   (1) 本契約締結前から乙が保有していた著作物、ノウハウ及び技術情報
   (2) 本業務と独立して乙が開発した汎用的なプログラム、モジュール、
       ライブラリ、開発用ツール及び設計手法
   (3) 第三者が権利を有するソフトウェア(オープンソースソフトウェアを含む)
3. 本件成果物に乙既存資産が組み込まれている場合、乙は甲に対し、
   本件成果物の利用に必要な範囲で、無償、非独占、譲渡不能かつ
   期間の定めのない使用許諾を行う。
4. 乙は、本件成果物について、甲及び甲の指定する者に対し
   著作者人格権を行使しない。ただし、甲は、乙の名誉又は声望を害する
   方法で本件成果物を利用してはならない。
5. 乙は、本業務の遂行を通じて得た一般的な知識、技能及び経験
   (甲の秘密情報を含まないものに限る。)を、他の業務において
   利用することができる。
```

**押さえどころ:**

- **2 項(乙既存資産の留保)がこの条文の全て。** 1 項を丸ごと飲んでも 2 項が入れば実害はほぼ消える
- **3 項(ライセンスバック)を必ずセットにする。** 2 項だけだと「乙の資産が入っているのに甲が使えない」状態になり、甲が納得しない。**留保 + 使用許諾のセットで初めて交渉が成立する**
- **1 項の「委託料を完済した時」** は支払確保の仕掛け。未払いのまま権利だけ移るのを防ぐ。地味だが強い
- **4 項ただし書**は名誉声望への配慮。全面不行使に抵抗がある場合の落としどころとして機能する(著作権法 113 条 11 項は名誉声望を害する利用を人格権侵害とみなす、という建て付けと整合する)
- **5 項(残存知識)** は再利用禁止条項への対抗。「知識・経験」と「成果物そのもの」を分けるのがポイント
- **2 項 3 号(第三者・OSS)は自分のためでもある。** OSS を含む納品で「一切の権利が甲に帰属」と約束すると、乙が履行不能な約束をしていることになる。**OSS を使う予定があるなら、別途 OSS リストの提出と条件の明示を約束する**方が誠実で、後の紛争も防ぐ

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **乙既存資産の留保 + ライセンスバック**(2・3 項) | 実害の本体。セットで出せば通りやすい |
| 2 | **一般的知識・経験の利用**(5 項) | ほぼ争いにならない。必ず取る |
| 3 | **OSS の扱いの明示**(2 項 3 号) | 甲にとってもリスク管理になるので通る |
| 4 | 委託料完済を移転条件に(1 項) | 支払サイトが長い相手ほど重要 |
| 5 | 27・28 条の削除 | **狙わない。** 筋が悪く、時間の無駄 |

**最低ライン:** 契約書本文が動かせないなら、**別紙で「乙既存資産リスト」を作って添付する**。「本件成果物には別紙記載の乙既存資産が含まれ、これらは第◯条の対象外とする」の一文を覚書で足すだけでも成立する。

**委託側(甲)なら:** 「一切の権利が帰属」だけ書いて安心しない。**乙が OSS や第三者ライブラリを組み込んでいた場合、その権利は譲渡されようがない**。以下を求める方が実効的:

- 納品時に**使用した OSS とライセンス条件の一覧**を提出させる
- **コピーレフト系(GPL 等)の使用は事前承諾制**にする
- 乙既存資産の留保を認める代わりに、**「甲の事業に必要な範囲で第三者への再許諾を含む」ライセンスバック**を取る(将来の M&A・事業譲渡で効く)

なお、**知的財産権の一方的な無償帰属を優越的地位を背景に求めることは、公正取引委員会の指針で問題となり得ると明示されている**(→ [law-notes.md](law-notes.md))。甲側でも、対価の妥当性を説明できる形にしておく方が安全。

## 6. 再委託の全面禁止

### 危険な原文の例

```
第◯条(再委託の禁止)
乙は、本業務の全部又は一部を第三者に再委託してはならない。
```

### 何が起きるか

**個人として受けている間は問題にならず、事業が伸びた瞬間に効いてくる。**

具体的なシナリオ:

- 案件が増えて**メンバーを増やしたい** → 業務委託で人を入れると契約違反 → 断るか、隠すか、契約を巻き直すかの三択
- **法人成りして自社の従業員に作業させる**場合の扱いが不明確(従業員は「第三者」か)。厳密に読むと違反になり得る書き方が多い
- デザイン・インフラなど**専門領域だけスポットで外注**することもできない
- **クラウドサービス・外部 API の利用**が「再委託」に当たるかが不明。厳格に読む相手だと AWS の利用すら議論になる
- 違反すると解除事由・違約金に紐付いていることが多く、**発覚時の打撃が大きい**

> **禁止条項が「守れないルール」になっているのが本当の問題。** 実際には外注しているのに契約上は禁止、という状態が一番危ない。**守れる条項に直すのが正解**であって、黙って運用でごまかすのは最悪。

### 修正案

```
第◯条(再委託)
1. 乙は、甲の事前の書面による承諾を得た場合、本業務の全部又は一部を
   第三者に再委託することができる。甲は、合理的な理由なく
   当該承諾を拒んではならない。
2. 前項にかかわらず、次の各号に該当する場合は、甲の承諾を要しない。
   (1) 乙の役員又は従業員に本業務を行わせる場合
   (2) 乙が事業の遂行のために通常利用するクラウドサービス、
       開発環境その他のツールを利用する場合
   (3) 本業務の内容に照らして軽微な補助的作業を委託する場合
3. 乙は、再委託先に対し、本契約に基づき乙が負う義務と
   同等の義務を負わせるものとし、再委託先の行為について
   自ら行ったものとして甲に対し責任を負う。
4. 乙は、甲の求めに応じ、再委託先の名称及び再委託する業務の
   内容を通知する。
```

**押さえどころ:**

- **2 項 1 号(従業員は再委託でない)が地味に一番大事。** 法人成りした後にここが曖昧だと毎回問題になる。**書いておけば議論が起きない**
- **1 項後段(合理的な理由なく拒めない)** が承諾制を実質的に機能させる。これが無いと「承諾制」は「実質禁止」と変わらない
- **3 項(再委託先の責任は乙が負う)を自分から書く。** 甲が再委託を嫌がる理由の 9 割は「知らない誰かが情報に触れる」ことなので、**責任を引き受ける姿勢を示すのが最短の通し方**
- **2 項 2 号(クラウド)** は現代の必須条項。SaaS・IaaS を「再委託」と解釈される余地を潰す
- 4 項(事前通知)は甲への譲歩として自分から差し出す。承諾制より軽く、甲の不安は解消される

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **従業員・クラウドの除外**(2 項 1・2 号) | 争いにならない。確認的な条項として通る |
| 2 | **承諾制への変更**(1 項) | 3 項をセットで出せば大抵通る |
| 3 | 合理的理由なく拒めない(1 項後段) | 押せれば取る。無くても実務は回る |
| 4 | 事前通知制(4 項)への緩和 | 承諾制が重い長期案件で狙う |

**最低ライン:** 全面禁止が動かないなら、**「乙の役員及び従業員に本業務を行わせることは再委託に該当しない」の一文だけ**は取る。これが無いと組織として仕事を受けられない。

**委託側(甲)なら:** 全面禁止は実は甲にとっても不利。**乙が守れない条項は、違反を隠す動機を作る**。承諾制にして再委託先を把握する方が、実際の情報管理としては強い。特に:

- **個人情報・秘密情報を扱う業務**は、再委託先への義務承継(3 項)を必ず書面で確保する
- 個人情報保護法上の**委託先監督義務は再委託先にも及ぶ**という前提で設計する(具体的な当てはめは弁護士・個人情報保護委員会のガイドラインで確認)
- 「承諾しない」より「**承諾の条件を明示する**」(秘密保持契約の締結、作業場所の限定など)方が運用しやすい

## 7. 競業避止の範囲・期間が過度

### 危険な原文の例

```
第◯条(競業避止)
乙は、本契約の有効期間中及び本契約終了後 5 年間、
甲の事業と競合する一切の業務を、自ら行い、又は第三者のために
行ってはならない。
```

### 何が起きるか

**「競合」の定義が無いまま広い禁止をかけられ、事業ができなくなる。**

具体的なシナリオ:

- 甲が「SaaS 事業者」だと、**あらゆる SaaS の受託開発が「競合」になり得る**。エンジニアとしての仕事の大半が禁止される
- 5 年は、この業界では**キャリアの一区切りに相当する長さ**。実質的に転業を強制される
- 地域の限定も、対価(補償金)も無い → **無償で 5 年間の営業活動を封じられる**
- 違反時の違約金条項とセットになっていることが多く、**額が大きい**(「委託料の 3 倍」など)

制度としての要点:

- **契約自由の原則があるので、競業避止条項そのものは違法ではない。** ただし範囲・期間・対価に照らして過度なものは、民法 90 条(公序良俗)により効力が争われることがある。**「無効です」と断定せず、「争いになり得るので弁護士に確認」と書く**
- **フリーランス(従業員を使用しない個人・一人法人)が相手の場合**、公正取引委員会等のガイドラインが「合理的に必要な範囲を超えた競業避止義務の一方的な設定」を優越的地位の濫用として問題になり得ると明示している(→ [law-notes.md](law-notes.md))。**受託側の交渉材料になる**
- ただし**交渉の場で「独禁法違反ですよ」と持ち出すのは筋が悪い。** 「範囲が広すぎて他の仕事が受けられなくなるので、具体的に限定させてほしい」という実務的な言い方の方が通る

### 修正案

```
第◯条(競業避止)
1. 乙は、本契約の有効期間中及び本契約終了後 1 年間、
   甲の秘密情報を利用して、次に定める行為を行ってはならない。
   (1) 別紙に特定する甲のサービス(以下「本件対象サービス」という。)と
       同一又は実質的に同一の機能を有するサービスを、
       自ら開発し又は運営すること
   (2) 本件対象サービスの競合事業者として別紙に列挙する事業者に対し、
       本件対象サービスと競合するサービスの開発を受託すること
2. 前項は、乙が本業務と独立して行う受託開発業務、
   乙既存資産を用いた事業その他一般的な業務を制限するものではない。
3. 甲が第 1 項の制限を本契約終了後 1 年を超えて求める場合、
   甲乙協議のうえ、その対価を別途定めるものとする。
```

**押さえどころ:**

- **「甲の事業と競合する」を「別紙に特定するサービス」に置き換える**のが本丸。抽象語を具体的な固有名詞に落とすと、範囲が一気に縮む
- **1 項柱書の「甲の秘密情報を利用して」** が効く。競業避止の正当な目的は情報の保護なので、目的に紐付けると自然に範囲が絞られる。**この 6 文字を入れるだけで実害が大きく減る**
- **2 項(一般業務は制限しない)** は確認規定だが、争いになったときの解釈の拠り所として価値がある
- **3 項(長期の制限には対価)** は交渉ツール。「1 年を超えるなら補償を」と言うと、多くの場合**相手が期間を短くする方を選ぶ**
- 期間は **1 年が交渉の基準線**。2 年までは実務でも見る。5 年は長い

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **対象の特定**(別紙・具体的サービス名) | 「どの事業と競合するのか教えてほしい」という自然な聞き方で入れる |
| 2 | **「秘密情報を利用して」の限定** | 目的に沿うので反対しにくい |
| 3 | **期間の短縮**(5 年 → 1〜2 年) | 数字の交渉。落としやすい |
| 4 | 一般業務の除外(2 項) | 確認規定として通りやすい |
| 5 | 対価の要求(3 項) | 期間短縮の交換材料として使う |

**最低ライン:** 何も動かないなら、**期間だけでも切る**(5 年 → 2 年)。期間も動かないなら、**「乙が本契約締結時点で既に行っている事業を除く」の一文**を取る。既存事業を止められるのが最悪の結果。

**委託側(甲)なら:** 広く書いても、いざ差止めや違約金請求をしようとすると**範囲の過度さを理由に効力を争われる**。守りたいものが「秘密情報」なのか「顧客」なのか「模倣サービス」なのかを特定し、そこだけを禁止する方が実効性が高い。特に**フリーランスが相手のときは、範囲・期間・補償の合理性を説明できる形にしておく**。

## 8. 引き抜き禁止が一方的

### 危険な原文の例

```
第◯条(従業員の引き抜き禁止)
乙は、本契約期間中及び本契約終了後 3 年間、甲の役員又は従業員を
雇用し、又は業務委託その他の名目により自己の業務に従事させては
ならない。違反した場合、乙は甲に対し、当該者の年間報酬額の
2 倍に相当する違約金を支払う。
```

### 何が起きるか

**片務性そのものが問題。** 乙は甲の人を採れないが、**甲は乙の人を採れる**。受託側は人が資産なので、この非対称は重い。

具体的なシナリオ:

- 常駐・準委任で長く入っていると、**甲が乙のメンバーを直接雇用する**動線ができる。契約上これを止められない
- 「業務委託その他の名目により」まで含むので、**元甲社員がフリーランスとして独立してきた場合に協業できない**。本人の意思で応募してきても違反になり得る書き方
- 「自己の業務に従事させてはならない」は範囲が広い。**再委託先が偶然その人を雇っていた**ケースまで拾い得る
- 違約金が定額(または報酬の倍数)で定められていると、**実損の有無に関係なく請求される**

### 修正案

```
第◯条(従業員の勧誘の禁止)
1. 甲及び乙は、本契約期間中及び本契約終了後 1 年間、
   相手方の役員又は従業員に対し、本業務を通じて知り得た
   関係を利用して、雇用又は業務委託を目的とする積極的な
   勧誘を行ってはならない。
2. 前項は、次の各号の場合には適用しない。
   (1) 一般に公開された求人募集に対する応募その他、
       相手方の役員又は従業員からの自発的な応募による場合
   (2) 相手方の役員又は従業員が、当該相手方を退職した日から
       6 か月を経過している場合
   (3) 相手方の書面による事前の同意を得た場合
3. 本条に違反した場合の損害賠償については、
   第◯条(損害賠償)の定めに従う。
```

**押さえどころ:**

- **「甲及び乙は」で双務化するのが最優先。** これを断る相手は理由を説明できないことが多く、交渉として通しやすい
- **「雇用してはならない」を「積極的な勧誘を行ってはならない」に変える。** 結果(雇用)の禁止から行為(勧誘)の禁止へ。**本人が自分の意思で来た場合まで責任を負わされない**ようにする
- **2 項 1 号(自発的応募の除外)** が実務上の生命線。公開求人への応募まで違反になると、採用活動そのものができなくなる
- **3 項(違約金条項を損害賠償条項に吸収)** で、定額違約金を外す。定額違約金は実損と切り離されるため受託側に不利。**外せないなら金額を下げる交渉に切り替える**
- 期間は 1 年が基準線。3 年は長い

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **双務化**(甲及び乙は) | 最も通しやすく、最も効く |
| 2 | **自発的応募の除外**(2 項 1 号) | 「採用活動が止まる」という具体論で押す |
| 3 | **「雇用」→「勧誘」への変更** | やや専門的だが説明すれば通る |
| 4 | 定額違約金の削除(3 項) | 削除が無理なら金額を下げる |
| 5 | 期間短縮(3 年 → 1 年) | 数字の交渉 |

**最低ライン:** **双務化と自発的応募の除外**の 2 点。ここだけ取れれば実務は回る。

**委託側(甲)なら:** 双務化を受け入れるのが実は得。**常駐案件では甲の社員が乙に引き抜かれるリスクも同程度にある**。また「雇用の禁止」は本人の職業選択に対する制約と評価される余地があるので、**勧誘行為の禁止に留める方が条項として安定する**。

## 9. 中途解約が委託者側にのみ認められている

### 危険な原文の例

```
第◯条(解約)
1. 甲は、1 か月前までに書面により通知することにより、
   いつでも本契約を解約することができる。
2. 乙は、本契約の有効期間中、本契約を解約することができない。
```

または、2 項が無く 1 項だけ書かれているパターン(乙の解約権について沈黙している)。

### 何が起きるか

**稼働を空けて待っているのに、相手はいつでも降りられる。**

具体的なシナリオ:

- 月 100 万円の準委任を 1 年契約で受け、**他の案件を断って稼働を空けた** → 2 か月目に解約通知 → 残り 10 か月の売上が消える。乙は他案件を断った損失を回収できない
- **乙側に解約権が無い**ので、条件が悪化しても、ハラスメントがあっても、抜けられない
- 解約時の**既履行分の精算方法が書かれていない**と、月の途中の解約で当月分をもらえるかが争いになる
- 開発途中で解約されると、**仕掛かりの成果物の扱いと報酬**が宙に浮く

制度としての要点:

- **請負では、注文者は仕事完成前ならいつでも損害を賠償して解除できる**(民法 641 条)。つまり**甲の任意解除権は民法上もともとある**。「解約させない」という交渉は筋が悪い。狙うべきは**「損害の賠償」の中身を契約で具体化すること**
- **委任(準委任)は各当事者がいつでも解除できる**(民法 651 条 1 項)。相手に不利な時期の解除等では損害賠償義務が生じ得る(同条 2 項)。**乙の解約権を封じる 2 項は、この規定と逆向き**なので、そもそも交渉の余地がある
- 請負が途中で解除されても、**可分な部分の給付で注文者が利益を受けるときは、その割合に応じた報酬を請求できる**(民法 634 条)。準委任にも同様の割合報酬の規定がある(民法 648 条 3 項)。**契約に書いておくと争いにならない**
- **相手がフリーランス(従業員を使用しない個人・一人法人)で、6 か月以上の業務委託の場合**、中途解除・不更新には 30 日前の予告義務が法律上ある(→ [law-notes.md](law-notes.md))。**契約書に無くても法律上の義務**なので、契約書が沈黙していても主張できる

### 修正案

```
第◯条(中途解約)
1. 甲及び乙は、相手方に対し 30 日前までに書面により通知することにより、
   本契約を解約することができる。
2. 甲が前項により解約した場合、甲は乙に対し、次の各号の合計額を
   支払うものとする。
   (1) 解約日までに乙が実施した業務に相当する委託料
       (可分な部分の給付により甲が利益を受ける部分を含む)
   (2) 乙が本業務のために既に支出した費用のうち、
       解約により無駄となるもの
   (3) 解約日の属する月の翌月分の委託料に相当する額
3. 乙が第 1 項により解約する場合、乙は、業務の引継ぎに必要な資料の
   提供その他合理的な協力を行う。
4. 本条は、第◯条(解除)に基づく債務不履行を理由とする解除を
   妨げない。
```

**押さえどころ:**

- **1 項の双務化が第一。** 「甲及び乙は」に直すだけで片務性が消える
- **2 項 3 号(1 か月分の補償)がこの条文の実利。** 予告期間 30 日 + 1 か月分の補償で、**実質 2 か月の稼働が守られる**。次の案件を探す時間として現実的な線
- **2 項 1 号は民法 634 条の割合報酬を契約に落としたもの。** 「仕掛かりでも払ってもらえる」を明文化しておくと、解約時の交渉が一瞬で終わる
- **3 項(乙が解約する場合の引継ぎ協力)を自分から入れる。** 双務化を通すための対価として差し出す。実際の負担は小さく、交渉効果は大きい
- **4 項**は、任意解約と債務不履行解除を混同させないための整理。相手の債務不履行時にまで 30 日待つ必要は無い

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **乙側の解約権**(双務化) | 3 項を差し出せば通る。準委任なら民法の建て付けを説明できる |
| 2 | **既履行分の精算の明文化**(2 項 1 号) | ほぼ争いにならない。必ず取る |
| 3 | **予告期間の延長**(1 か月 → 2 か月) | 補償が取れないときの代替。数字の交渉 |
| 4 | 補償(2 項 3 号) | 継続案件・専属性が高い案件ほど強く主張できる |

**最低ライン:** **既履行分の精算の明文化**と、**予告期間が 30 日以上あること**。補償まで取れなくても、この 2 つがあれば致命傷は避けられる。

**委託側(甲)なら:** 乙に解約権を与えると、繁忙期に抜けられるリスクがある。ただし**解約権を封じても、実際に働かない人を働かせることはできない**。現実的な守り方は、解約権は双務にしたうえで、**予告期間を長めに取る(60 日)**、**引継ぎ義務を具体化する**(ドキュメント・アカウント・ソースの引渡しを列挙)、**引継ぎ完了までは委託料の一部を留保する**。

## 10. 秘密保持が無期限 / 秘密情報の定義が無限定

### 危険な原文の例

```
第◯条(秘密保持)
1. 乙は、本契約に関連して甲から開示された一切の情報を秘密として
   保持し、第三者に開示又は漏洩してはならない。
2. 前項の義務は、本契約終了後も期間の定めなく存続する。
```

### 何が起きるか

**「一切の情報」は、守れないルールを作る。**

具体的なシナリオ:

- **甲の会社名すら秘密**になる → 実績として公表できない。エンジニア個人にとって**職務経歴が書けない**のは実害が大きい
- 打ち合わせで聞いた**業界の一般的な話**も形式上は「開示された情報」に含まれる → 他社との会話で無自覚に違反する
- **無期限の保持義務**は、10 年後に「あのときの資料をまだ持っているか / 消したか」を証明する負担を残す。実務上、証明できない
- 除外規定(公知情報・独自開発情報など)が無いと、**新聞に載った情報を話しても違反**という不合理な状態になる
- **目的外使用の禁止が無い**と、逆に「秘密にはするが使ってよい」と読める。NDA として穴がある(→ 開示側なら必ず入れる)

> **秘密保持は「厳しくすると安全」ではない。** 守れない条項は、違反状態を常態化させ、いざというとき「どうせみんな守っていない」という反論を招く。**守れる範囲に絞るのが、開示側にとっても正しい。**

### 修正案

```
第◯条(秘密保持)
1. 本契約において「秘密情報」とは、甲又は乙が相手方に対し、
   書面、電磁的記録その他の方法により開示した情報であって、
   秘密である旨を明示したものをいう。口頭又は視覚により開示した
   情報については、開示の際に秘密である旨を告げ、かつ開示後
   14 日以内に書面によりその内容を特定した場合に限り、
   秘密情報に含まれるものとする。
2. 前項にかかわらず、次の各号に該当する情報は秘密情報に
   含まれない。
   (1) 開示の時点で既に公知であった情報
   (2) 開示後、受領者の責めによらず公知となった情報
   (3) 開示の時点で受領者が既に保有していた情報
   (4) 受領者が正当な権限を有する第三者から秘密保持義務を
       負うことなく取得した情報
   (5) 受領者が秘密情報によらず独自に開発又は取得した情報
3. 受領者は、秘密情報を本契約の目的以外に使用してはならない。
4. 受領者は、法令、裁判所又は行政機関の要求により開示を求められた
   場合、必要な範囲で秘密情報を開示することができる。
   この場合、受領者は可能な限り事前に開示者に通知する。
5. 本条の義務は、本契約終了後 3 年間存続する。
   ただし、営業秘密として管理されている技術上の情報については、
   本契約終了後 5 年間とする。
6. 乙は、甲の事前の書面による承諾を得て、本業務の実績を
   自らの事業紹介の目的で公表することができる。
   甲は、合理的な理由なく当該承諾を拒んではならない。
```

**押さえどころ:**

- **1 項(秘密である旨の明示要件)がこの条文の骨。** 「一切の情報」から「マル秘表示があるもの」に絞ると、何が秘密かが管理可能になる。**口頭情報の書面化手続(14 日以内)** をセットにするのが標準形
- **2 項(除外事由 5 類型)は NDA の定型。** 無い契約書は雑に作られていると見てよい。**5 号(独自開発)** は開発者にとって特に重要 — 似たものを独自に作ったときの逃げ道
- **3 項(目的外使用の禁止)は開示側にとって本体。** 秘密保持だけだと「秘密のまま自社で使う」を止められない。**自分が開示側になるときは必ず確認する**
- **5 項の期間**: 3〜5 年が実務の相場。無期限を主張されたら「営業秘密として管理している技術情報だけ長め」に分ける折衷案を出す
- **6 項(実績公表)** は受託側の実利。**フリーランス・小規模事業者にとって実績の公表を過度に制限することは、公正取引委員会等のガイドラインで問題となり得ると示されている**(→ [law-notes.md](law-notes.md))。ただし交渉では法律論より「営業上どうしても必要」という実務論で押す方が通る
- **返還・破棄**の条項も要確認。「破棄し、その旨を証明する書面を提出する」は負担が重い。「破棄又は消去する。ただしバックアップ媒体上に残存する複製については、消去に代えて秘密保持義務を継続する」が現実的

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **除外事由**(2 項) | 定型条項なので必ず通る。無ければ必ず入れる |
| 2 | **秘密の定義の絞り込み**(1 項) | 「管理できる形にしたい」で押す |
| 3 | **期間の限定**(5 項) | 無期限 → 5 年は通りやすい |
| 4 | 実績公表(6 項) | 承諾制でよい。断られても「社名を伏せた記載は可」まで詰める |

**最低ライン:** **除外事由**だけは必ず入れる。定義も期間も動かせないなら、せめて「公知情報・独自開発情報を含まない」の一文を足す。

**委託側 / 開示側なら:** 明示要件(1 項)を厳しくすると、**マル秘表示を忘れた情報が保護されなくなる**。運用が回らないなら「本契約に関連して開示される情報のうち、その性質上秘密として扱われるべきことが明らかなもの」という受け皿を足す。加えて**目的外使用の禁止(3 項)と、残存記憶条項が入っていないか**を必ず確認する(→ [checklist.md](checklist.md#c-nda秘密保持契約) の C-4 残留記憶条項)。

## 11. 合意管轄が相手方所在地

### 危険な原文の例

```
第◯条(合意管轄)
本契約に関する一切の紛争については、甲の本店所在地を管轄する
地方裁判所を第一審の専属的合意管轄裁判所とする。
```

### 何が起きるか

**争う気を最初から削がれる。** これが目的の条項でもある。

具体的なシナリオ:

- 甲が福岡、乙が東京 → **100 万円の未払いを取り立てるために福岡地裁に通う** → 交通費と時間で回収額を超える → 泣き寝入り
- 弁護士も、遠方の裁判所だと**日当・交通費が上乗せ**される。小額案件では費用倒れになる
- 逆に、**甲から訴えられる側になったときも遠方**で応訴することになる
- 「専属的」の 3 文字が効いていて、他の裁判所に訴えても移送される

> **金額が小さい契約ほど、この条項の実害が大きい。** 500 万円の案件なら遠方でも争うが、80 万円なら諦める。**日常的な受託業務ほど優先度を上げるべき条項。**

### 修正案

**第一希望(自分の所在地):**

```
第◯条(合意管轄)
本契約に関する一切の紛争については、乙の本店所在地を管轄する
地方裁判所を第一審の専属的合意管轄裁判所とする。
```

**折衷案 A(被告地主義):**

```
第◯条(合意管轄)
本契約に関する一切の紛争については、訴えを提起される当事者の
本店所在地を管轄する地方裁判所を第一審の専属的合意管轄裁判所とする。
```

**折衷案 B(中立地・協議前置):**

```
第◯条(協議及び合意管轄)
1. 本契約に関して紛争が生じた場合、甲及び乙は、まず誠実に
   協議によりその解決を図るものとする。
2. 前項の協議によっても解決しない場合、東京地方裁判所を
   第一審の専属的合意管轄裁判所とする。
```

**押さえどころ:**

- **折衷案 A(被告地主義)が最も通しやすい。** 「どちらか一方に有利にしない」という説明が使え、相手も断りにくい。実質的には**「訴える側が遠方に行く」ので、濫訴の抑止にもなる**
- 「専属的」を「非専属的」に変えるだけでも意味がある。**法定管轄が生きるので、選択肢が増える**
- **1 項(協議前置)を足すのは低コストで効果がある。** 相手も反対しにくく、実際に訴訟前の協議機会が確保される
- **仲裁条項(JCAA 等)には安易に飛びつかない。** 一審制で早いが、費用が高く、少額案件には向かない。**受託側の小口案件ではむしろ不利**

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **被告地主義**(折衷案 A) | 公平性を説明できる。最も通る |
| 2 | **「専属的」の削除** | 一語の修正なので通りやすい |
| 3 | 協議前置(折衷案 B の 1 項) | ほぼ反対されない |
| 4 | 自分の所在地 | 力関係で押せるときだけ |

**最低ライン:** 動かないなら**受け入れてよい**。ただし「この契約は、争いになったら実質的に諦めることになる」と認識したうえで、**他の条項(特に損害賠償の上限、支払条件)を厳しめに見る**。管轄が不利なら、そもそも紛争が起きない設計にするしかない。

**委託側(甲)なら:** 自社所在地の管轄は当然入れたい条項。ただし**相手が争えないことは、相手が支払わないことを止められない**わけではない。少額の未払い回収は**支払督促**という簡便な手続もあるので、管轄条項だけを守りの柱にしない。

## 12. 一方的な自動更新

### 危険な原文の例

```
第◯条(契約期間)
本契約の有効期間は、20XX 年 ◯ 月 ◯ 日から 1 年間とする。
ただし、期間満了の 3 か月前までに甲乙いずれからも
書面による申出がないときは、同一条件でさらに 1 年間更新される。
以後も同様とする。
```

より悪い形:

```
ただし、期間満了の 3 か月前までに甲から書面による申出がないときは、
同一条件でさらに 1 年間更新される。
```

(**乙には更新拒絶権が無い**)

### 何が起きるか

**気づいたときには次の 1 年が確定している。**

具体的なシナリオ:

- 3 か月前予告 + 1 年更新 → **更新拒絶できる窓が年に一度、数日単位で開くだけ**。カレンダーに入れていなければ確実に逃す
- 単価が据え置きのまま「同一条件で」更新される → **相場が上がっても値上げのタイミングが来ない**
- SaaS の年額契約で同じ構造 → 使っていないツールに毎年課金され続ける
- 乙に更新拒絶権が無い形は、実質的に**期限の無い契約**

> **これは条項の不利さより「運用で落とす」タイプのリスク。** 契約締結時に**更新拒絶の期限をカレンダーに登録する**ところまでやって初めて対処が完了する。契約レビューの成果物に「◯年◯月◯日までに更新可否を判断」と日付を書いて渡す。

### 修正案

```
第◯条(契約期間)
1. 本契約の有効期間は、20XX 年 ◯ 月 ◯ 日から 20XX 年 ◯ 月 ◯ 日まで
   とする。
2. 期間満了の 1 か月前までに、甲又は乙のいずれからも
   書面による更新拒絶の申出がない場合、本契約は同一の条件で
   さらに 1 年間更新されるものとし、以後も同様とする。
3. 甲及び乙は、期間満了の 2 か月前までに、次期の委託料その他の
   取引条件について協議することができる。当該協議が調わない場合、
   いずれの当事者も前項による更新を拒絶することができる。
4. 甲は、期間満了の 2 か月前までに、乙に対し更新の意向を
   確認するものとする。
```

**押さえどころ:**

- **2 項の双務化(「甲又は乙のいずれからも」)が最優先。** 片務的な更新条項は交渉で必ず直す
- **予告期間を短くする**(3 か月 → 1 か月)。窓が広くなるほど落としにくくなる
- **3 項(条件協議権)が実利。** 「同一条件で自動更新」は単価改定の機会を奪う。**協議を申し入れる権利と、協議不調時の更新拒絶権**をセットで入れる。これが無いと値上げ交渉の入口が無い
- **4 項(相手からの意向確認義務)** は保険。忘れても相手が声をかけてくれる仕組みにする。通れば運用リスクが大きく下がる
- **更新後の期間を短くする**(1 年 → 6 か月)交渉も有効。相手が渋る場合、更新は 1 年のままで 3 項を取る方に集中する

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **双務化** | 片務なら必ず直す。反対する理由が説明できない |
| 2 | **条件協議権**(3 項) | 「物価・単価の変動に対応するため」で押す。今は通りやすい |
| 3 | **予告期間の短縮**(3 か月 → 1 か月) | 数字の交渉 |
| 4 | 意向確認義務(4 項) | ダメ元。通れば楽 |

**最低ライン:** 条項が一切動かないなら、**契約レビューの成果物に更新拒絶の期限日を明記して渡す**。これはレビューの一部であって、省略してはいけない。「◯年◯月◯日(更新拒絶期限)までに継続可否を判断すること」と書く。

**委託側(甲)なら:** 自動更新は運用コストの削減として合理的。ただし**乙側の更新拒絶権を封じるのは避ける**。継続の意思が無い相手を契約で縛っても品質は出ない。**条件協議の機会を設ける方が、長期的には安定した関係になる**。

## 13. 支払サイトが長すぎる / 検収後起算で無限に伸びる

### 危険な原文の例

```
第◯条(委託料の支払)
甲は、検収完了後、乙の請求に基づき、請求書を受領した月の
翌々月末日までに、乙の指定する口座に振り込む方法により
委託料を支払う。振込手数料は乙の負担とする。
```

### 何が起きるか

**納品から入金まで 4 か月以上空く構造。** 起算点が「検収完了」で、検収の期限が無い([3](#3-みなし検収がない))と、支払期日そのものが無期限に後ろへ動く。

具体的なシナリオ:

- 4/10 納品 → 検収が 5 月末までかかる → 6/30 に請求書 → **翌々月末 = 8/31 入金**。納品から 4 か月半、資金繰りが持たない
- 検収が止まると支払期日が発生しないので、**遅延損害金すら請求できない**(期日が到来していないため)
- **振込手数料が乙負担**なのは慣行として見るが、少額案件を積み上げると無視できない

法制度としての要点(**2026 年 1 月 1 日に法律名と条番号が変わっている**。詳細と出典は [law-notes.md](law-notes.md)):

- **中小受託取引適正化法(取適法)** — 旧・下請代金支払遅延等防止法(下請法)。2026 年 1 月 1 日施行の改正で名称が変更され、条番号も移動した。**「下請法 2 条の 2」と書くと古い**
  - **支払期日は、給付を受領した日から 60 日以内**(取適法 3 条 1 項)。条文上「**検査をするかどうかを問わず**」と明記されており、**検収が遅れても 60 日の壁は動かない**。ここが最大の武器
  - **遅延利息は年 14.6%**(取適法 6 条、公正取引委員会規則)
  - 適用には資本金 / 従業員数の要件がある。**ソフトウェア(プログラム)開発の委託は 3 億円区分**(5000 万円区分ではない)。改正で**従業員数基準(300 人 / 100 人)も追加された**
- **フリーランス法(特定受託事業者に係る取引の適正化等に関する法律)**
  - 相手が**従業員を使用しない個人・一人法人**なら、**資本金要件なしで適用される**
  - **支払期日は、給付を受領した日から 60 日以内でできる限り短い期間**(同法 4 条)。こちらも「**検査をするかどうかを問わず**」
  - **再委託の場合の例外あり**(再委託である旨等を明示した場合に限り、元委託の支払期日から 30 日以内)
  - **遅延利息の規定は無い**(取適法との違い)

> **法律を交渉で振りかざす前に、適用があるか確認する。** 資本金・従業員数の要件を満たさない相手に「下請法違反です」と言うと、間違っているうえに関係も壊れる。**適用がある場合でも、「60 日を超えると御社側の義務に触れる可能性があるので」という言い方**にする。

### 修正案

```
第◯条(委託料の支払)
1. 甲は、乙が本件成果物を納入した日(以下「納入日」という。)から
   起算して 30 日以内に、乙の指定する口座に振り込む方法により
   委託料を支払う。ただし、当該支払期日は、いかなる場合においても
   納入日から起算して 60 日を超えないものとする。
2. 検収が完了していないことは、前項の支払期日の到来を妨げない。
3. 振込手数料は甲の負担とする。
4. 甲が支払期日までに支払を行わないときは、支払期日の翌日から
   支払済みに至るまで、年 14.6% の割合による遅延損害金を支払う。
```

分割払にする場合(**長期案件では強く推奨**):

```
第◯条(委託料の支払方法)
委託料は、次のとおり分割して支払う。
(1) 本契約締結日から 15 日以内に、委託料の 30%(着手金)
(2) 別紙工程表に定める中間成果物の納入日から 30 日以内に、
    委託料の 30%
(3) 本件成果物の納入日から 30 日以内に、委託料の 40%
```

**押さえどころ:**

- **起算点を「納入日」という乙が動かせる日にするのが本丸。** 「検収完了後」だと相手が期日を握る。**2 項(検収未完了は期日到来を妨げない)** をセットで入れて逃げ道を塞ぐ
- **1 項ただし書(60 日上限)** は、取適法・フリーランス法いずれの適用がある場合でも整合する形。**適用が無い相手にも「業界標準として」入れられる**
- **4 項の遅延損害金 14.6%** は、法定利率(年 3%)よりはるかに高い。**取適法の遅延利息率に合わせた数字**として説明でき、通りやすい
- **分割払が最も効く対策。** 支払サイトを 30 日に縮める交渉より、**着手金 30% を取る交渉の方が通ることが多い**。資金繰りへの効果も大きい
- 振込手数料は交渉のカードとして使う。取りにいって、他で譲る材料にする

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **起算点を納入日に**(1 項・2 項) | 検収に人質を取られる構造を外す。最重要 |
| 2 | **着手金・分割払** | サイト短縮より通りやすく、効果が大きい |
| 3 | **60 日上限の明記** | 法令の建て付けに沿うので反論しにくい |
| 4 | 遅延損害金 14.6% | 通れば督促の材料になる |
| 5 | 支払サイトの短縮(翌々月末 → 翌月末) | 相手の経理締めの都合があるので最後に |

**最低ライン:** 「翌々月末」が動かせないなら、**着手金だけでも取る**。それも無理なら、**検収期限を明記させる**([3](#3-みなし検収がない))。支払サイトの問題は、実は検収の問題であることが多い。

**委託側(甲)なら:** 経理の締め処理の都合で「翌々月末」にしている会社は多いが、**取適法・フリーランス法の 60 日規制に抵触しないか必ず検算する**。月末締め翌々月末払いは、月初納品だと 90 日近くになる。**自社が委託側のときこそ、この 2 法の適用有無を先に確認しておく**。

## 14. 請負と準委任の取り違え(表題と実質の乖離)

### 危険な原文の例

```
業務委託契約書(準委任)

第 1 条(業務内容)
乙は、甲に対し、別紙に定めるシステムの開発業務を行う。

第 ◯ 条(成果物)
乙は、20XX 年 ◯ 月 ◯ 日までに、本件システムを完成させ、
甲に納入する。納入した成果物が本契約の内容に適合しない場合、
乙は無償で修補する。

第 ◯ 条(報酬)
報酬は月額 ◯ 円とし、稼働時間が 140 時間を下回る場合は
時間按分により減額する。
```

### 何が起きるか

**「準委任」と書いてあるのに、完成義務と契約不適合責任を負っている。** 表題を信じて「完成の責任は無い」と思い込むと、実際には請負として扱われる。

具体的なシナリオ:

- 準委任だと思って稼働ベースで進めた → **納期に完成しない** → 「完成義務がある」と言われて債務不履行を問われる
- 逆に、報酬は稼働時間で減額される(準委任的)のに、**責任は完成責任(請負的)** という**受託側に一方的に不利なハイブリッド**になっている。これが実務で最も多いパターン
- 契約類型が不明確だと、**中途解約時の報酬の扱い**が決まらない(請負なら民法 634 条の割合報酬、準委任なら 648 条 3 項)
- **偽装請負のリスク**: 「業務委託」と書いてあっても、甲が乙の作業者に直接指揮命令していると、労働者派遣に該当すると評価され得る(厚生労働省の「労働者派遣事業と請負により行われる事業との区分に関する基準」— 昭和 61 年労働省告示第 37 号。→ [law-notes.md](law-notes.md))

制度としての要点:

| | 請負 | 準委任 |
|---|---|---|
| 根拠 | 民法 632 条 | 民法 656 条(委任の規定を準用) |
| 義務 | **仕事を完成させること** | **善管注意義務**をもって事務を処理すること(民法 644 条) |
| 報酬 | 仕事の結果に対して | 事務処理に対して(履行割合型)/ 成果に対して(成果完成型、民法 648 条の 2) |
| 契約不適合責任 | あり(民法 636 条・637 条) | 原則として無い(善管注意義務違反の問題になる)。ただし成果完成型は 634 条を準用 |
| 中途終了時の報酬 | 可分な部分で注文者が利益を受ける割合(民法 634 条) | 既にした履行の割合(民法 648 条 3 項) |
| 委託者の任意解除 | 完成前ならいつでも(損害賠償を要する。民法 641 条) | いつでも(民法 651 条) |

> **表題ではなく条文の実質で判断される。** レビューでは必ず「**完成義務があるか**」「**契約不適合責任を負うか**」「**報酬が成果に紐付くか稼働に紐付くか**」の 3 点を見て、表題と一致しているかを確認する。**一致していなければ、それ自体が指摘事項。**

### 修正案

**準委任として整理する場合(稼働ベースで受けるとき):**

```
第 1 条(業務の内容)
1. 甲は乙に対し、別紙に定める業務(以下「本業務」という。)の
   遂行を委託し、乙はこれを受託する。本契約は準委任契約とし、
   乙は本件システムの完成義務を負わない。
2. 乙は、善良な管理者の注意をもって本業務を遂行する。

第 ◯ 条(報酬)
1. 報酬は月額 ◯ 円とし、月間稼働時間が ◯ 時間を超え ◯ 時間以内で
   あることを前提とする。
2. 稼働時間が下限を下回った場合又は上限を超えた場合、
   超過又は不足 1 時間あたり ◯ 円により精算する。

第 ◯ 条(成果物)
乙は、本業務の遂行状況を月次で甲に報告する。
乙が本業務の過程で作成した中間成果物は、
その完成又は特定の品質を保証するものではない。
```

**請負として整理する場合(完成責任を負うとき):**

```
第 1 条(業務の内容)
甲は乙に対し、別紙仕様書に定める本件システムの開発及び
納入を委託し、乙はこれを請け負う。

第 ◯ 条(報酬)
報酬は金 ◯ 円(固定)とする。稼働時間による増減は行わない。
```

**押さえどころ:**

- **「本契約は準委任契約とし、乙は完成義務を負わない」を明記する**のが最も効く一文。これが無いと、他の条項から請負性が読み取られる
- **請負なら報酬は固定にする。** 「完成責任は負うが報酬は稼働で減る」は最悪の組み合わせ。**どちらか一方の性質に揃える**
- 準委任にするなら、**契約不適合責任の条項を削除する**。残っていると請負性の証拠になる
- **成果完成型の準委任**(民法 648 条の 2)という選択肢もある。「成果に報酬を紐付けたいが、完成義務までは負いたくない」ときの中間解。ただし条文設計が難しいので、**金額が大きい案件では弁護士に見てもらう**
- **偽装請負の予防**: 「甲は、乙の従業員に対して直接業務上の指揮命令を行わないものとし、業務に関する連絡は乙の責任者を通じて行う」という条項を入れる。**常駐案件では必須**

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **類型の明記と条文の整合** | 「どちらのつもりか確認したい」で始める。相手も混乱していることが多く、素直に直る |
| 2 | **準委任なら完成義務の否定を明記** | 一文で済む。必ず取る |
| 3 | **請負なら報酬固定 + 仕様の確定** | 完成責任を負う以上、完成の定義を確定させる |
| 4 | 指揮命令系統の条項(常駐時) | 甲にとってもリスク回避になるので通りやすい |

**最低ライン:** **表題と実質が食い違っていることを指摘し、どちらのつもりかを相手に確認する**。契約書を直せなくても、認識のすり合わせを記録に残せば争いの芽は小さくなる。

**委託側(甲)なら:** 「準委任」と書いて完成責任を期待するのは危険。**完成を求めるなら請負として設計し、仕様と検収基準を確定させる**。逆に、要件が固まっていない探索的な開発なら、素直に準委任にして稼働で払う方が、結果的に安く早く終わることが多い。

## 15. 第三者の権利侵害の補償が無限定

### 危険な原文の例

```
第◯条(第三者の権利侵害)
乙は、本件成果物が第三者の著作権、特許権その他の権利を
侵害しないことを保証する。本件成果物に関して第三者から
請求、訴訟その他の紛争が生じた場合、乙は自らの責任と費用に
おいてこれを解決し、甲に一切の損害を及ぼさないものとする。
```

### 何が起きるか

**「侵害しないことを保証する」は、事実上不可能な保証。**

具体的なシナリオ:

- **特許は非侵害の調査に多額の費用がかかり、完全な保証はできない。** 全世界の特許を調べ切ることは現実的に不可能
- **甲が指定したライブラリ・API・素材**に問題があった場合まで乙が負う書き方になっている
- **甲が納品後に改変**して侵害状態になった場合も、文言上は乙の責任
- 「一切の損害を及ぼさない」= [1](#1-損害賠償の上限がない) の上限条項の適用外に置かれる。**損害賠償に上限を入れても、この条項が抜け道になる**
- 訴訟対応の費用(弁護士費用)まで乙負担。**訴訟が起きた時点で、勝っても負けても大打撃**

> **[1](#1-損害賠償の上限がない) とセットで見る。** 賠償上限を勝ち取っても、知財補償条項が「上限の対象外」に置かれていれば意味が半減する。**上限条項との関係を明示させる**のがレビューの要点。

### 修正案

```
第◯条(第三者の権利侵害)
1. 乙は、本件成果物が第三者の著作権を侵害しないことについて、
   本契約締結時点において乙が知る限りにおいて保証する。
2. 本件成果物に関して第三者から権利侵害を理由とする請求を
   受けた場合、甲は速やかに乙に通知し、乙に防御の機会及び
   必要な協力を与えるものとする。甲は、乙の事前の書面による
   同意なく、当該請求について和解し又は責任を認めてはならない。
3. 乙は、前項の請求が乙の責めに帰すべき事由による場合、
   自らの選択により、次の各号のいずれかの措置を講ずる。
   (1) 権利者から必要な権利又は使用許諾を取得すること
   (2) 侵害を回避するよう本件成果物を修正又は代替すること
   (3) 上記が合理的な費用で実施できない場合、
       本件成果物の返還を受け、委託料を返還すること
4. 次の各号に起因する権利侵害については、乙は責任を負わない。
   (1) 甲が提供し又は指定した資料、仕様、素材、ソフトウェア
       又はサービスに起因するもの
   (2) 甲又は第三者による本件成果物の改変に起因するもの
   (3) 本件成果物を本契約で予定した用途以外に使用したことに
       起因するもの
   (4) 本件成果物を甲又は第三者の製品若しくはサービスと
       組み合わせたことに起因するもの
5. 本条に基づく乙の責任は、第◯条(損害賠償)に定める上限に服する。
```

**押さえどころ:**

- **1 項の「著作権」への限定と「知る限りにおいて」がこの条文の核。** 特許・意匠まで無条件保証するのは実務上不可能。**著作権(自分が書いたコードだから分かる)だけを保証し、特許は知る限りに留める**のが誠実かつ現実的
- **5 項(損害賠償上限への服従)を絶対に入れる。** これが無いと [1](#1-損害賠償の上限がない) の努力が無駄になる。**レビューでここを見落とすのが典型的な失敗**
- **2 項(防御の機会 / 単独和解の禁止)** は自分を守る条項。甲が勝手に高額和解して乙に請求してくるのを防ぐ
- **3 項(措置の選択権)** で「訴訟に付き合って費用を出し続ける」以外の出口を作る。3 号の**委託料返還による打ち切り**が最終的な逃げ道
- **4 項(免責事由)** が実質的な範囲限定。特に 1 号(甲の指定)と 4 号(組み合わせ)は入れておく
- **OSS の扱い**は別に整理する([5](#5-著作権の全部譲渡--著作者人格権不行使) の 2 項 3 号)。OSS ライセンス違反はこの条項ではなく、使用 OSS リストの提出と甲の承諾で管理する

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **損害賠償上限への服従**(5 項) | 一文。必ず取る |
| 2 | **免責事由**(4 項) | 「甲さんの指定した素材の問題まで負えない」で通る |
| 3 | **特許を保証範囲から外す / 知る限りに限定** | 「特許調査には費用がかかるので、必要なら別途見積もる」と言うと通りやすい |
| 4 | 措置の選択権(3 項) | 押せれば取る |
| 5 | 防御の機会(2 項) | 甲にとっても合理的なので通りやすい |

**最低ライン:** **5 項(上限への服従)と 4 項 1 号(甲の指定に起因するものの免責)。** この 2 つが無い知財補償条項は、他の防御を全部無効化する。

**委託側(甲)なら:** 「一切の損害を及ぼさない」と書いても、乙に支払能力が無ければ回収できない。実効的なのは、**納品時に使用した OSS・第三者コンポーネントの一覧を提出させる**、**生成 AI を使った場合はその旨と使用範囲を申告させる**、**主要な機能について乙が権利者であることを表明保証させる**、といった前段の管理。加えて、乙が個人・小規模事業者なら**上限を報酬額にしても実質的な損はない**(取れないものは取れない)ので、交渉材料として譲る余地がある。

## 16. 仕様変更・やり直しが無償で無限に発生する

### 危険な原文の例

```
第◯条(業務の変更)
甲は、必要と認めるときは、本業務の内容を変更することができる。
乙は、これに従うものとする。

第◯条(修正)
乙は、甲の指示に基づき、本件成果物の修正を行う。
```

または、**変更管理の条項が丸ごと無い**パターン。

### 何が起きるか

**固定報酬なのに作業量が青天井になる。** 請負の固定報酬と、無制限の変更権が同居すると、実質的な時給がいくらでも下がる。

具体的なシナリオ:

- 「ちょっとした変更」の積み重ねで**当初見積の 2 倍の工数**になる。追加請求の根拠が契約に無い
- 検収の場で変更要望が出る → [3](#3-みなし検収がない)・[4](#4-検収基準が主観的) と結合し、**検収が終わらない**
- 納期はそのまま、仕様だけ増える → **遅延の責任は乙が負う**
- 「甲の指示に基づき修正」は、修正の原因が乙の不備なのか甲の心変わりなのかを区別していない。**区別が無いと全部無償になる**

制度としての要点:

- **相手が取適法・フリーランス法の適用対象なら、「不当な給付内容の変更・やり直し」は禁止行為として定められている**(→ [law-notes.md](law-notes.md))。**費用を負担せずに変更・やり直しをさせる行為**が対象
- ただし**交渉で使うのは最後**。まずは「変更管理の手続を決めましょう」という建設的な入り方をする

### 修正案

```
第◯条(仕様変更)
1. 甲又は乙は、本件業務の内容、仕様、納期その他の条件の変更を
   希望する場合、変更の内容及び理由を記載した書面により
   相手方に申し入れる。
2. 前項の申入れがあった場合、甲及び乙は、変更の可否、
   委託料の増減、納期の変更その他必要な事項について
   速やかに協議する。
3. 前項の協議が調い、書面により合意した場合に限り、
   変更が確定するものとする。協議が調うまでの間、
   乙は変更前の内容に従って本業務を継続すれば足りる。
4. 甲が変更を申し入れたことにより乙に追加の作業が生じる場合、
   甲は乙に対し、当該作業に相当する委託料を追加して支払う。

第◯条(やり直し)
1. 乙は、本件成果物が別紙検収基準に適合しない場合、
   自らの費用で修正を行う。
2. 前項に該当しない修正(甲の要望に基づく変更、甲が提供した
   情報の誤りに起因する修正、甲による仕様の追加を含む)は、
   前条(仕様変更)の手続によるものとし、
   乙は追加の委託料を請求することができる。
```

**押さえどころ:**

- **3 項後段(協議が調うまで変更前の内容で継続すればよい)が地味に強い。** これが無いと「協議中だが作業は始めてほしい」で無償作業が発生する
- **やり直し条項の 1 項 / 2 項の切り分けが本体。** 「乙の不備による修正(無償)」と「甲の都合による変更(有償)」を条文で分ける。**この境界線を契約書に書くことが、追加請求の唯一の根拠になる**
- **4 項(追加報酬)** を明記する。「協議する」だけだと「協議したが増額しない」で終わる
- **書面合意を要件にする**(3 項)。口頭の「じゃあそれで」を積み重ねると後で立証できない。**メールでも「書面」に含める**定義を置く
- 大きな案件では、**変更管理表(CR: Change Request)の様式を別紙で決める**ところまでやる

### 交渉の落としどころ

| 順位 | 取るもの | 理由 |
|---|---|---|
| 1 | **やり直しの有償 / 無償の切り分け** | 追加請求の根拠。最重要 |
| 2 | **変更は書面合意で確定**(3 項) | 「認識齟齬を防ぐため」で通る |
| 3 | **協議中は変更前の内容で継続**(3 項後段) | 押せれば取る |
| 4 | 追加報酬の明記(4 項) | 「協議する」止まりでも実務は回るが、あった方が強い |

**最低ライン:** 条項が入らないなら、**運用で残す**。変更要望が出るたびに「この変更で ◯ 人日の追加、納期は ◯ 日後ろ倒しになります」とメールで返す。**記録が積み上がれば、契約書に条項が無くても交渉の材料になる。**

**委託側(甲)なら:** 変更管理を入れると「変更のたびに金を取られる」ように見えるが、実際は**無制限の変更権が品質と納期を壊す**。変更が有償だと明示されている方が、社内の要望を整理する規律が働く。ただし乙の不備によるやり直しまで有償にされないよう、**検収基準への不適合は乙負担**を明記しておくこと(上記 1 項)。

## 危険な組み合わせ

単独ではよくある条項でも、**組み合わさると質が変わる**。以下が揃っていたら、個別の指摘ではなく「契約全体の構造として受け入れ難い」と総評に書く。

| 組み合わせ | 何が起きるか |
|---|---|
| [3](#3-みなし検収がない) みなし検収なし + [4](#4-検収基準が主観的) 主観基準 + [16](#16-仕様変更やり直しが無償で無限に発生する) 無償やり直し | **報酬の発生自体が相手の善意頼み**になる。作業は無限、入金はゼロ |
| [1](#1-損害賠償の上限がない) 賠償上限なし + [2](#2-契約不適合責任の期間が長すぎる--無期限) 責任期間無期限 | **何年経っても青天井の責任が残る**。事業のリスクとして計上不能 |
| [1](#1-損害賠償の上限がない) 上限を入れた + [15](#15-第三者の権利侵害の補償が無限定) 知財補償が上限の対象外 | **上限条項が無意味になる**。上限を取って安心した瞬間が一番危ない |
| [5](#5-著作権の全部譲渡--著作者人格権不行使) 権利全部譲渡 + 再利用禁止 + [7](#7-競業避止の範囲期間が過度) 競業避止 | **同種の事業を今後できなくなる**。1 案件と引き換えに事業ドメインを失う |
| [3](#3-みなし検収がない) 検収期限なし + [13](#13-支払サイトが長すぎる--検収後起算で無限に伸びる) 検収後起算の支払 | **支払期日が発生しない**。遅延損害金すら請求できない |
| [11](#11-合意管轄が相手方所在地) 遠方管轄 + 少額案件 | **どの条項も実効性を失う**。争えない契約は、条文どおりに運用されない |
| [9](#9-中途解約が委託者側にのみ認められている) 片務解約 + [7](#7-競業避止の範囲期間が過度) 競業避止 + [12](#12-一方的な自動更新) 片務自動更新 | **相手はいつでも降りられるのに、こちらは縛られ続ける** |

## 育て方

実際に交渉した結果をここに還元する。**通った / 通らなかったの結果を「交渉の落としどころ」の表に反映する**のが最も価値が高い — 順位は実績で並べ替えるべきもの。

- 新しい類型の危険条項に出会ったら、**同じ 4 部構成**(危険な原文 / 何が起きるか / 修正案 / 落としどころ)で追加する
- 修正案が実際に締結された条文になったら、**その文言に差し替える**(通った実績のある文言が最強)
- 法令・ガイドラインを追記するときは、**必ず [law-notes.md](law-notes.md) に一次情報の URL とともに記録してから**本文で参照する
