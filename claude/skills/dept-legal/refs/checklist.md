# 契約類型別チェックリスト

SKILL.md 本体のチェックリストを、**契約類型ごとに展開したもの**。類型が違えば見るべき点も違う。

> **使い方:** ①まず契約の類型を確定する(表題ではなく実質 → [clauses.md #14](clauses.md#14-請負と準委任の取り違え表題と実質の乖離))→ ②該当する類型のリストを**上から順に**当てる → ③ヒットしたら [clauses.md](clauses.md) の該当項で修正案を作る。
>
> **✅ は「あると有利 / あるべき」、⚠️ は「あると不利」、❓ は「無いこと自体が問題」。** 特に **❓(不在)を拾い落とすのが最大の失敗パターン** — 契約書を読んで違和感が無いのに危険、という形で現れる。

## 類型の見分け方

| 表題 | 実質を見るポイント | 適用するリスト |
|---|---|---|
| 業務委託契約書 | **完成義務があるか / 契約不適合責任を負うか / 報酬が成果に紐付くか稼働に紐付くか** | [請負型](#a-業務委託契約請負型) or [準委任型](#b-業務委託契約準委任型) |
| 開発委託契約書・請負契約書 | 表題どおりのことが多いが、報酬が稼働ベースなら要確認 | [請負型](#a-業務委託契約請負型) |
| 秘密保持契約書・NDA | **一方向か相互か。目的の定義があるか** | [NDA](#c-nda秘密保持契約) |
| 利用規約・利用契約・サービス利用約款 | **一方的変更条項があるか。データの扱いが書いてあるか** | [SaaS・利用規約](#d-利用規約saas-契約) |
| 発注書 / 注文請書のみ | **基本契約書が別にあるか。無ければ裏面約款を必ず読む** | [契約書がない場合](#e-発注書注文請書だけで契約書がない場合) |
| 基本契約書 + 個別契約書 | **どちらが優先するかの条項** | 基本契約に類型別リスト + [基本/個別の優先関係](#f-基本契約--個別契約の組み合わせ) |
| **相手が自社のグループ会社 / 兼任役員がいる** | **表題は関係ない。両社に同じ人が取締役として入っているか** | 類型別リスト + [グループ会社間取引](#g-グループ会社間兼任役員がいる取引)。**契約書を読む前に承認手続きを確認する** |

## A. 業務委託契約(請負型)

**完成義務を負う。** 成果物ができなければ報酬が発生しない前提で、責任の範囲を切る作業が中心になる。

### A-1. 類型と業務範囲

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **業務範囲が別紙・仕様書で特定されているか** | 「本件システムの開発」だけだと、どこまでやれば完成かが決まらない。**完成の立証ができず、報酬請求が成り立たない** |
| ❓ | **納品物の一覧**(ソース、設計書、テスト結果、手順書)があるか | 「ドキュメントも当然含まれる」と主張され、見積外の作業が発生する |
| ❓ | **前提条件・スコープ外**が書いてあるか | 「甲が◯◯を提供することを前提」「本件に含まれないもの: 保守、移行、教育」を書かないと、全部含まれると読まれる |
| ⚠️ | 「等」「その他付随する一切の業務」 | **範囲が無限に広がる。** 見つけたら削るか、例示に限定させる |
| ❓ | **甲の協力義務**(資料提供、環境提供、キーマンのアサイン、レビュー期限)があるか | 甲の遅れで納期が守れなくても、乙が遅延の責任を負う |

### A-2. 検収 → [clauses.md #3](clauses.md#3-みなし検収がない)・[#4](clauses.md#4-検収基準が主観的)

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **検査期間の明記** | 検収が永遠に終わらない。支払も発生しない |
| ❓ | **みなし検収**(期間内に通知がなければ合格) | 相手が放置するだけで報酬が発生しない状態が続く |
| ❓ | **検収基準**(別紙・仕様書への紐付け) | 「甲が満足するまで」が実質基準になり、無限修正 |
| ❓ | 不合格通知に**理由の記載義務**があるか | 「不合格です」の一言で期限がリセットされ続ける |
| ❓ | **再検査の範囲が指摘部分に限定**されているか | 再納入のたびに全体を見直され、新しい指摘が生える |
| ⚠️ | 検収が**甲の社内承認・稟議**に紐付いている | 乙が関与できない社内事情で検収が止まる |

### A-3. 契約不適合責任 → [clauses.md #2](clauses.md#2-契約不適合責任の期間が長すぎる--無期限)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **期間が無期限 / 5 年など長期** | 何年経っても無償改修に呼び戻される |
| ⚠️ | **起算点が「甲が発見した時」** | 実質無期限。**期間の長短より、ここが致命的** |
| ✅ | 起算点が**検収完了日**という客観日 | 期限が確定し、リスクを見積もれる |
| ❓ | **免責事由**(甲の指図・甲の改変・稼働環境の変更・運用不遵守) | 自分のせいでない不具合まで無償で直す羽目になる |
| ❓ | 本条の責任が**損害賠償の上限に服する**旨 | 上限条項を取っても、この条項が抜け道になる |
| ⚠️ | 「無償で修補する」だけで**修補以外の選択肢が無い** | 作り直しが実質不可能なものを無限に押し付けられる |

### A-4. 知的財産 → [clauses.md #5](clauses.md#5-著作権の全部譲渡--著作者人格権不行使)・[#15](clauses.md#15-第三者の権利侵害の補償が無限定)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **「一切の成果物」の全部譲渡** | 汎用ユーティリティ・共通処理まで手放し、次の案件で書けなくなる |
| ❓ | **乙既存資産の留保**(契約前から持っていたもの、汎用ライブラリ) | 自社の資産を 1 案件と引き換えに失う |
| ❓ | **ライセンスバック**(留保した資産の使用許諾) | 留保だけだと甲が納品物を使えず、そもそも交渉が成立しない |
| ⚠️ | **「著作者人格権を譲渡する」** | **著作権法 59 条により譲渡できない。** この誤りは契約書全体の作り込みを疑う根拠になる → [law-notes.md](law-notes.md#2-著作権法昭和-45-年法律第-48-号) |
| ✅ | 著作者人格権の**不行使特約** | 甲側の正当な要求。争わない |
| ✅ | **27 条・28 条の特掲** | 甲側が入れてくるのが正当。削除交渉は筋が悪い |
| ⚠️ | **成果物の再利用禁止 / 同種サービスの提供禁止** | 実質的な競業避止として機能する。[#7](clauses.md#7-競業避止の範囲期間が過度) と合わせて評価 |
| ❓ | **一般的な知識・技能・経験の利用が留保**されているか | 学んだことを次に使えない、という不合理な状態になる |
| ❓ | **OSS の扱い**(使用の可否、リスト提出、ライセンス条件) | 履行不能な保証をすることになる。**甲側にとってもリスク** |
| ❓ | 第三者権利侵害の補償が**賠償上限に服する**か | 上限条項が無効化される |
| ⚠️ | 特許を含む**無条件の非侵害保証** | 実務上不可能な保証。著作権 + 知る限り、に絞る |
| ❓ | **生成 AI の使用**についての定めがあるか | 近年増えている条項。禁止されているのに使うと契約違反。**逆に定めが無いと後で争いになる** |

### A-5. 報酬・支払 → [clauses.md #13](clauses.md#13-支払サイトが長すぎる--検収後起算で無限に伸びる)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | 支払期日の**起算点が「検収完了後」** | 検収が止まると支払期日が発生せず、遅延損害金すら請求できない |
| ✅ | 起算点が**納入日** + 検収未完了は期日到来を妨げない旨 | 相手に人質を取られない |
| ⚠️ | **受領から 60 日超**の支払サイト | 取適法・フリーランス法の適用があれば問題になり得る → [law-notes.md](law-notes.md) で規模要件を確認 |
| ❓ | **着手金・分割払**があるか | 長期案件で資金繰りが持たない。**サイト短縮より通りやすい交渉** |
| ❓ | **遅延損害金**の定め | 法定利率(年 3%)しか請求できない。14.6% を入れると督促の材料になる |
| ⚠️ | 振込手数料が乙負担 | 少額案件を積み上げると効く。交渉のカードに使う |
| ❓ | **消費税**の扱いが明記されているか | 「金 100 万円」だけだと税込か税抜かで揉める |
| ❓ | **源泉徴収**の扱い(個人事業主の場合) | 手取り額の認識がずれる |
| ❓ | **経費・交通費**の負担と精算方法 | 「実費は甲負担」を書かないと持ち出しになる |
| ⚠️ | **手形払い・電子記録債権** | 取適法の適用があれば原則禁止(2026 年改正)。適用が無くても資金繰りリスク |
| ❓ | 相手が**適格請求書発行事業者**か / こちらの登録番号の記載要求 | インボイス制度の要件。国税庁の情報で確認する |

### A-6. 変更管理 → [clauses.md #16](clauses.md#16-仕様変更やり直しが無償で無限に発生する)

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **仕様変更の手続条項** | 固定報酬のまま作業量が青天井になる |
| ❓ | **有償やり直し / 無償やり直しの切り分け** | 追加請求の根拠が契約に無くなる。**これが変更管理の本体** |
| ❓ | 変更は**書面合意で確定**する旨 | 口頭の「じゃあそれで」を後で立証できない |
| ❓ | 協議中は**変更前の内容で継続**すればよい旨 | 「協議中だが作業は始めてほしい」で無償作業が発生 |
| ❓ | 変更に伴う**納期の変更**が書いてあるか | 仕様だけ増えて納期は据え置き、遅延責任は乙 |

### A-7. 責任 → [clauses.md #1](clauses.md#1-損害賠償の上限がない)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **損害賠償の上限が無い** | 報酬 100 万円の案件で賠償 1 億円があり得る。**常に最優先** |
| ❓ | **間接損害・逸失利益の除外** | 「サイトが 3 日止まった分の売上」を請求される |
| ❓ | 上限条項が**双方向**か | 片務的な免責は交渉で通りにくい。自分から双務にする |
| ✅ | **故意・重過失の除外**が入っているか | 入れておかないと「上限条項ごと無効」と争われる余地が広がる |
| ❓ | **責任期間の限定**(引渡し後 1 年以内の請求に限る等) | 上限額を取っても期間が無限だとリスクが読めない |
| ❓ | **不可抗力**条項 | 災害・大規模障害・法令変更で履行できないときに債務不履行を問われる |
| ⚠️ | **違約金・損害賠償額の予定**が定額で置かれている | 実損の有無に関係なく請求される。金額の妥当性を必ず見る |

### A-8. 拘束 → [clauses.md #6](clauses.md#6-再委託の全面禁止)・[#7](clauses.md#7-競業避止の範囲期間が過度)・[#8](clauses.md#8-引き抜き禁止が一方的)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **再委託の全面禁止** | 人を増やせない。**法人成りしたときに実害が出る** |
| ❓ | **従業員・クラウドが再委託から除外**されているか | 自社従業員に作業させることが違反になり得る書き方が多い |
| ⚠️ | **競業避止の対象が「甲の事業と競合する一切」** | 事業ドメインを失う。別紙で具体的サービスに特定させる |
| ⚠️ | 競業避止の**期間が 3 年以上 / 対価が無い** | 民法 90 条(公序良俗)で効力が争われ得る。**「無効」と断定せず弁護士に確認と書く** |
| ⚠️ | **引き抜き禁止が片務的** | 乙は甲の人を採れないが甲は乙の人を採れる |
| ❓ | 引き抜き禁止に**自発的応募の除外**があるか | 公開求人への応募まで違反になり、採用活動が止まる |
| ⚠️ | **専属義務**(他社業務の禁止) | 実質的に雇用と同じ拘束。フリーランス相手なら公取委ガイドラインの論点 |

### A-9. 秘密保持 → [C. NDA](#c-nda秘密保持契約) のリストを当てる

契約書内の秘密保持条項も、NDA と同じ観点で見る。加えて:

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **実績公表の可否** | 職務経歴・営業資料に書けない。承諾制でもよいので入れる |
| ❓ | **存続条項**に秘密保持が入っているか(甲側の関心) | 契約終了と同時に義務が消える |

### A-10. 終わり方 → [clauses.md #9](clauses.md#9-中途解約が委託者側にのみ認められている)・[#12](clauses.md#12-一方的な自動更新)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **中途解約が甲だけ** | 条件が悪化しても抜けられない |
| ❓ | **既履行分の精算**が明文化されているか | 途中解約時に仕掛かり分の報酬が宙に浮く。民法 634 条の割合報酬を契約に落としておく |
| ❓ | 解約の**予告期間**(30 日以上あるか) | 明日から仕事が無くなる |
| ⚠️ | **自動更新が片務的**(甲だけが更新拒絶できる) | 実質的に期限の無い契約 |
| ❓ | 更新時の**条件協議権** | 「同一条件で自動更新」だと単価改定の機会が来ない |
| ❓ | **解除事由**が双方に定められているか | 相手の支払遅延で解除できない |
| ❓ | **期限の利益喪失・倒産時**の扱い | 相手が破綻したときに仕掛かり分を回収できない |
| ❓ | **存続条項**の範囲が適切か | 秘密保持・知財・賠償が終了後も残るのは通常。**競業避止まで無期限に残っていないか**を見る |

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **合意管轄が相手方所在地** | 少額案件では実質的に争えない → [clauses.md #11](clauses.md#11-合意管轄が相手方所在地) |
| ❓ | **準拠法**(相手が外国法人のとき) | 外国法が準拠法だと弁護士費用が跳ね上がる |

## B. 業務委託契約(準委任型)

**完成義務を負わない。** 善管注意義務をもって事務を処理する契約(民法 656 条 → 644 条)。**見るべき点が請負とはっきり違う。**

> **請負型リストとの最大の違い:** 検収・契約不適合責任は原則として論点にならない代わりに、**稼働時間の精算・指揮命令関係・解約予告**が中心論点になる。**請負型リストをそのまま当てると的外れになる。**

### B-1. 類型の明確化 → [clauses.md #14](clauses.md#14-請負と準委任の取り違え表題と実質の乖離)

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **「乙は完成義務を負わない」の明記** | 他の条項から請負性が読み取られ、完成責任を問われる |
| ⚠️ | **契約不適合責任の条項が残っている** | 準委任と書いてあっても請負として扱われる根拠になる |
| ⚠️ | **「完成させ、納入する」という文言** | 同上。**準委任なら削る** |
| ⚠️ | **完成責任を負うのに報酬は稼働で減額される** | 受託側に一方的に不利なハイブリッド。**実務で最も多い形** |
| ❓ | **履行割合型か成果完成型か**が判別できるか | 成果完成型(民法 648 条の 2)なら中途終了時の扱いが変わる |

### B-2. 稼働と報酬

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **月間稼働時間の下限・上限**(例: 140〜180 時間) | 「月額固定」だけだと、稼働がいくら増えても報酬が変わらない |
| ❓ | **超過・不足時の精算単価** | 上下限を書いても精算方法が無ければ機能しない |
| ⚠️ | **上限だけ定めて超過精算が無い** | 上限を超えた分がすべて無償になる |
| ⚠️ | **下限割れの減額はあるが超過の増額が無い** | 片務的。必ず双方向にする |
| ❓ | **稼働時間の記録・報告方法** | 精算の根拠が無く、水掛け論になる |
| ❓ | **月の途中で開始 / 終了した場合の日割り** | 初月・最終月で揉める |
| ❓ | **稼働時間に含まれるもの**(打ち合わせ、移動、待機、障害対応) | 「作業時間のみ」と解釈され、会議の時間が無償になる |

### B-3. 指揮命令・偽装請負 → [law-notes.md](law-notes.md#6-労働者派遣法偽装請負)

**常駐・準常駐案件では必ず見る。**

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **甲は乙の従業員に直接指揮命令しない**旨の条項 | 実態次第で労働者派遣に該当すると評価され得る |
| ❓ | **乙側の責任者(窓口)**が定められているか | 指揮命令系統が甲に一本化され、偽装請負の徴表になる |
| ⚠️ | **始業終業時刻・休憩・休日を甲が指示**する条項 | 37 号告示 2 条 1 号ロに直接該当する |
| ⚠️ | **甲が乙の作業者を選任・交代させる権限**を持つ条項 | 同 1 号ハ(配置の決定・変更)に該当し得る |
| ⚠️ | **甲の朝礼・勤怠システムへの参加義務** | 実態面での徴表。契約書に書いてあれば削る |
| ❓ | **業務の遂行方法を乙が決められる**旨 | 「自ら行う企画又は専門的技術・経験に基づいて処理」(同 2 号ハ(2))の裏付け |

> **契約書を直しても運用が伴わなければ意味がない。** レビューでは「契約書上は問題ないが、実際に甲の担当者が直接作業指示をしていないか」を**ヒアリングして確認する**。これは書面からは分からない。

### B-4. 報告義務と成果物

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **報告の頻度・形式**(月次報告書等) | 善管注意義務を尽くしたことの立証手段が無くなる |
| ⚠️ | **中間成果物に品質保証を求める条項** | 準委任の性質と矛盾。完成責任の入口になる |
| ❓ | 作成した**中間成果物の権利の帰属** | 準委任でも成果物は生まれる。譲渡か留保かを決めておく |

### B-5. 終わり方(準委任特有)

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **双方の中途解約権**(民法 651 条は双方にいつでもの解除権を認める) | 片務条項は民法の建て付けと逆向き。**交渉の余地がある** |
| ❓ | **予告期間**(30 日以上) | 稼働を空けて待っているのに翌月から仕事が無くなる |
| ❓ | **既にした履行の割合に応じた報酬**(民法 648 条 3 項)の明文化 | 月の途中の解約で当月分が払われるかが争いになる |
| ❓ | **引継ぎの範囲と期間** | 終了後も無限に質問対応させられる / 逆に引継ぎ不足で揉める |
| ⚠️ | **相手がフリーランスで 6 か月以上の委託なのに、30 日前予告の定めが無い** | フリーランス法 16 条の予告義務は**契約書に書いていなくても法律上の義務** → [law-notes.md](law-notes.md#4-フリーランス法) |

### B-6. 請負型リストから流用する項目

以下は準委任でも同じように見る。**上にスクロールして A の該当節を当てること。**

- **A-5 報酬・支払**(支払期日、着手金、消費税、源泉、経費、手形)
- **A-7 責任**(賠償上限、間接損害の除外、双務性、不可抗力、違約金)
- **A-8 拘束**(再委託、競業避止、引き抜き、専属義務)
- **A-9 秘密保持**(→ C のリスト)
- **A-11 その他**(管轄、準拠法、反社、個人情報、譲渡禁止、一方的変更権)

## C. NDA(秘密保持契約)

→ 条文レベルの修正案は [clauses.md #10](clauses.md#10-秘密保持が無期限--秘密情報の定義が無限定)

**NDA は「短いから安全」ではない。** 1 枚の紙で事業の自由度を数年縛れる。**特に自分が受領者側のときは、本契約より丁寧に読む。**

### C-1. まず確定させる: 一方向か相互か

| 型 | 自分の立場 | 見る重心 |
|---|---|---|
| **一方向(片務)** — 相手だけが開示者 | **受領者** | 義務の重さ。定義の広さ、期間、目的外使用、残留物の扱い |
| **一方向(片務)** — 自分だけが開示者 | **開示者** | 保護の十分さ。**目的外使用の禁止**、再開示先の限定、違反時の措置 |
| **相互(双務)** | 両方 | **義務が本当に対称か。** 「甲は〜、乙は〜」と書き分けている条項に非対称が仕込まれていることがある |

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | 「相互」と題しながら**義務の記述が非対称** | 実質は片務。条項ごとに主語を追って確認する |
| ❓ | 自分が**開示もする予定なのに片務 NDA** | こちらが出した情報が保護されない。**相互に直す交渉をする** |

### C-2. 目的の定義

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **「本目的」が具体的に定義**されているか | 目的が無いと「目的外使用の禁止」が機能しない。**目的外使用の禁止は目的の定義とセットで初めて効く** |
| ⚠️ | 目的が「**両社の取引に関する検討**」など広すぎる | 相手が何にでも使えることになる。開示者なら必ず絞る |
| ⚠️ | 目的が**狭すぎる**(受領者側の視点) | 通常業務での利用まで違反になり得る |
| ❓ | **目的外使用の禁止**条項があるか | 秘密保持だけだと「秘密のまま自社で使う」を止められない。**開示者側の最重要項目** |

### C-3. 秘密情報の定義

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **「一切の情報」「開示された全ての情報」** | 会社名も、雑談で聞いた業界の話も秘密になる。**守れないルールになる** |
| ✅ | **秘密である旨の明示**(マル秘表示等)を要件にしている | 何が秘密かが管理可能になる。受領者側の第一希望 |
| ❓ | **口頭・視覚開示の書面化手続**(開示後 14 日以内等) | 明示要件だけだと口頭情報が一切保護されない(開示者側の穴) |
| ❓ | **除外事由 5 類型**(①開示時に公知 ②受領者の責によらず公知 ③開示時に既に保有 ④第三者から適法に取得 ⑤独自開発) | 新聞に載った情報を話しても違反、という不合理が起きる。**無い NDA は雑に作られている** |
| ❓ | **⑤独自開発の除外**があるか | エンジニアにとって最重要。似たものを独自に作ったときの唯一の逃げ道 |
| ❓ | **本契約の存在・内容自体**が秘密情報に含まれるか | 含まれると、他社に「◯◯社と NDA を結んでいる」とすら言えない |

### C-4. 残留記憶条項(residuals)

**受領者に有利 / 開示者に不利**な条項。**見落とされやすいので独立して確認する。**

典型的な文言:

```
受領者の従業員が秘密情報に接したことにより記憶に残った一般的な
知識、技能及び経験については、本契約の秘密保持義務の対象と
しないものとし、受領者はこれを自由に使用することができる。
```

| | チェック | これが無いと / あると |
|---|---|---|
| ✅ | **自分が受領者なら、あると有利** | 「見た情報を忘れられない」という現実に対応できる。**エンジニアにとっては実務上必要** |
| ⚠️ | **自分が開示者なら、あると危険** | 「記憶に残った」の一言で保護が抜ける。**ソースコード・設計・顧客リストを見せる場合は絶対に外す** |
| ❓ | 残留記憶の範囲が「**一般的な知識・技能・経験**」に限定されているか | 限定が無いと、具体的な設計・データまで自由に使えることになる |
| ❓ | 「**意図的に記憶した場合を除く**」等の限定があるか | 開示者側の妥協点。丸ごと削れないときはここを取る |

> **大手 IT 企業のひな形には residuals が入っていることが多い。** 相手の NDA に入っていて、自分が開示側になる予定があるなら**必ず指摘する**。逆に自分が受領側だけなら、あえて触れない判断もある。

### C-5. 期間

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **秘密保持義務が無期限** | 10 年後に「消したか」を証明する負担が残る。実務上証明できない |
| ❓ | **契約自体の有効期間**と**秘密保持義務の存続期間**が区別されているか | 「本契約は 1 年」だけだと、情報の保護も 1 年で切れる(開示者に不利) |
| ✅ | 存続期間が **3〜5 年** | 実務の相場。無期限を主張されたら「技術情報だけ長め」の折衷案を出す |
| ❓ | 期間の**起算点**(契約終了時か、各情報の開示時か) | 「開示時から 3 年」だと情報ごとに満了日が違い、管理不能 |

### C-6. 返還・破棄

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **「破棄し、その旨を証明する書面を提出する」** | 実務上、証明書の発行は負担が重い。**バックアップやログに残る分をどうするか答えが無い** |
| ✅ | 「破棄又は消去する。ただし**バックアップ媒体上の複製は、消去に代えて秘密保持義務を継続する**」 | 現実的な落としどころ |
| ❓ | **法令・社内規程による保存義務**への配慮があるか | 監査対応で保存が必要な記録まで消す義務を負う |

### C-7. その他

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **差止請求 + 違約金**が定額で置かれている | 実損と切り離された請求を受ける。金額の妥当性を必ず見る |
| ⚠️ | **競業避止・引き抜き禁止が NDA に紛れ込んでいる** | 「NDA だから」と軽く見て署名すると事業を縛られる。**A-8 のリストを当てる** |
| ⚠️ | **知的財産の帰属条項が NDA に入っている** | 検討段階で生まれたアイデアの権利を持っていかれる。[clauses.md #5](clauses.md#5-著作権の全部譲渡--著作者人格権不行使) を当てる |
| ❓ | **法令・裁判所の要求による開示**の例外があるか | 法令に従うと契約違反、という板挟みになる |
| ❓ | **役員・従業員・再委託先への開示**が認められているか | 社内で共有できないと業務が回らない。「同等の義務を負わせる」条件付きで認めさせる |
| ❓ | **NDA を締結せずに情報を出させられていないか**(自分が開示側) | 相手が優越的地位にある場合、公取委の指針が問題視する類型 → [law-notes.md](law-notes.md#5-独占禁止法公取委ガイドライン) |

## D. 利用規約・SaaS 契約

**交渉できないことが多い。** だから**「読んで、受け入れるかどうかを決める」**のがレビューの目的になる。「修正案を出す」ではなく「**このリスクを飲むか**」を示す。

> **業務で使うサービスの規約は、自社の契約と同じ重さで見る。** 顧客データを預けるなら、そのサービスの規約が自社の顧客に対する責任の上限になる。

### D-1. まず見る 3 点

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **一方的変更条項**の有無と、変更時の通知方法 | 「当社は本規約を随時変更できる」+ 通知が Web 掲示のみ = **気づかないうちに条件が変わる** |
| ❓ | **データの所有・利用範囲** | 入力したデータを事業者が自由に使える規約がある。**顧客データを入れる前に必ず確認** |
| ❓ | **解約時のデータ返還・削除** | 解約した瞬間にデータが消え、取り出せない |

### D-2. 免責・責任

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **免責範囲が「一切の責任を負わない」** | 障害でこちらの事業が止まっても救済が無い |
| ❓ | **賠償上限**(過去 12 か月の利用料相当額 等) | 上限があるのが通例。**その額が自社のリスクに見合うか**を評価する |
| ⚠️ | **SLA が無い / 努力目標に過ぎない** | 稼働率の保証が無い。基幹業務に使ってよいかの判断材料 |
| ❓ | SLA 違反時の**救済**(利用料返金 / クレジット)の内容 | 「返金のみ」だと実損は回収できない。**そのリスクを飲めるか** |
| ⚠️ | **サービス終了・機能廃止の予告期間**が短い / 定めが無い | 移行の時間が取れない。**代替手段の有無を先に考えておく** |

### D-3. データ

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | 入力データを**事業者がサービス改善・AI 学習に利用**できる条項 | 顧客の秘密情報を預けている場合、**自社の NDA 違反になり得る** |
| ❓ | **オプトアウトの手段**があるか | 学習利用を止められないなら、扱えるデータの種類が限られる |
| ❓ | **データの保存場所・越境移転** | 個人情報保護法上の外国第三者提供の論点。顧客への説明義務にも関わる |
| ❓ | **解約後のデータ保持期間**(30 日以内にエクスポート可能 等) | 解約と同時に消えると、移行の猶予が無い |
| ❓ | **エクスポート形式**(標準形式か、独自形式か) | 出せても使えない形式だと実質ロックイン |
| ❓ | **サブプロセッサ(再委託先)の一覧・変更通知** | 自社の顧客に対する再委託の説明ができない |
| ❓ | **セキュリティインシデント時の通知義務**と期限 | 漏えいを知るのが報道より遅くなる |

### D-4. 契約の続き方・終わり方

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **年額プランの自動更新 + 長い予告期間** | 気づいたら次の 1 年が確定 → [clauses.md #12](clauses.md#12-一方的な自動更新)。**契約時にカレンダーに登録するところまでやる** |
| ❓ | **中途解約時の返金**の有無 | 年額前払いで解約しても返金されないのが通例。**そのつもりで契約する** |
| ⚠️ | **値上げ条項**(事業者が自由に価格を変更できる) | 予算が立たない。更新前の通知期間を確認する |
| ⚠️ | **アカウント停止・利用制限**の事由が広い / 事業者の裁量 | 業務が突然止まる。**基幹業務に使うなら重い** |
| ❓ | **準拠法・管轄が外国**(海外 SaaS) | 実質的に争えない。リスクとして計上する |

### D-5. 自分が SaaS を提供する側なら

利用規約を**作る / 見直す**ときのチェック。

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **消費者向けか事業者向けか**が明確か | 消費者向けなら消費者契約法の規律がかかる。**免責条項の書き方が変わるので、弁護士に確認する** |
| ❓ | 定型約款としての**変更手続**が適切か | 一方的変更の有効性は民法の定型約款の規定に関わる。**条番号の当てはめは弁護士の領分** |
| ❓ | **賠償上限・免責の書き方** | 「一切責任を負わない」は、相手が消費者だと効力を争われやすい |
| ❓ | **禁止事項・アカウント停止事由**が具体的か | 抽象的だと運用で恣意的になり、逆に紛争を招く |
| ❓ | **データの取り扱い**をプライバシーポリシーと整合させているか | 規約とポリシーで食い違うと、どちらも信用されない |

## E. 発注書・注文請書だけで契約書がない場合

**「契約書が無い = 契約が無い」ではない。** 発注書と注文請書のやりとりで契約は成立している。問題は**中身が薄いこと**と、**裏面約款で不利な条件が入っていること**。

### E-1. 最初に確認する

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **裏面約款・別紙約款があるか** | PDF の 2 ページ目、「取引基本条件」へのリンク、「当社発注条件に従う」の一文。**ここに本体がある** |
| ❓ | **基本契約書が過去に締結されていないか** | 「◯年◯月◯日付基本契約書に基づき」と書かれていたら、その基本契約が本体 |
| ❓ | **相手のひな形に「当社の購買基本条件による」等の参照**があるか | 見たことのない条件が組み込まれる。**必ず取り寄せて読む** |
| ⚠️ | 注文請書に**署名・押印して返送**しようとしている | 返送した瞬間に裏面約款ごと合意したことになる。**返送前に読む** |

### E-2. 発注書に最低限必要な事項

**無ければ、メールで確認して記録に残す。**「発注書に書いていないから確認しました」というやりとり自体が証拠になる。

| | 項目 | 無いとどうなるか |
|---|---|---|
| ❓ | **業務内容・成果物の特定** | 何を納めれば完了かが決まらず、報酬請求の根拠が立たない |
| ❓ | **金額**(税抜 / 税込の別) | 消費税分で揉める |
| ❓ | **納期** | 遅延の基準が無い。逆に「いつまでも催促される」状態にもなる |
| ❓ | **検収の方法と期限** | 検収が終わらず支払が発生しない |
| ❓ | **支払期日と支払方法** | 「請求書を出したのに払われない」の起点が定まらない |
| ❓ | **契約類型**(請負か準委任か) | 完成義務の有無が不明。争いになると不利な方で解釈されがち |
| ❓ | **著作権の帰属** | 定めが無いと原則として創作者(乙)に残るが、**「報酬を払ったのだから当社のもの」と主張されて揉める** |
| ❓ | **注文者・受注者の正式名称** | 相手が親会社なのか子会社なのか、請求先が変わる |

> **相手が取適法・フリーランス法の適用対象なら、取引条件の明示は法律上の義務**(取適法 4 条 / フリーランス法 3 条)。**「発注書をください」と言うのは正当な要求**であって、遠慮する話ではない → [law-notes.md](law-notes.md)

### E-3. 発注書が来ない / 口約束で始まっている

**最も危険なパターン。** 契約書が無いこと自体より、**合意内容の証拠が無いこと**が問題。

| 対応 | やること |
|---|---|
| **1. 自分から書面を出す** | 「以下の内容で承知しました」と業務内容・金額・納期・支払期日を書いたメールを送る。**返信で「はい」と来れば、それが合意の証拠** |
| **2. 見積書を出して承諾をもらう** | 見積書 + 「この内容で発注します」の返信で、契約成立の証拠になる |
| **3. 議事録を残す** | 打ち合わせで決まったことを箇条書きにして送る。訂正が無ければ合意とみなせる |
| **4. 作業を始める前に出す** | 着手後に条件を確定させようとすると、足元を見られる。**着手前が唯一の交渉タイミング** |

> **レビューで「契約書がありません」と指摘して終わらない。** 上記のどれをやるか、**具体的な次の一手まで書く**。文面の下書きまで出せるとなお良い。

## F. 基本契約 + 個別契約の組み合わせ

| | チェック | これが無いと / あると |
|---|---|---|
| ❓ | **優先関係の条項**(どちらが優先するか) | 条件が食い違ったときにどちらが効くか分からない。**個別契約優先が通常だが、明記が必要** |
| ⚠️ | **基本契約優先**と書いてある | 個別契約で有利な条件を取っても、基本契約の不利な条項に上書きされる |
| ❓ | **個別契約の成立方法**(発注書 + 請書か、発注後◯日で自動成立か) | 「発注書を出せば請書が無くても成立」だと、こちらの意思確認なしに契約が立つ |

## G. グループ会社間・兼任役員がいる取引

**自社と、自分(または自社の取締役)が支配・兼任する別会社との間の取引。** 事業の切り出し、子会社への発注、兄弟会社間の受発注。

**⚠️ この類型は契約書のレビューでは足りない。** 条項が全部きれいでも、**承認手続きを飛ばすと取締役個人の責任問題になる**。契約書を読む前に下記を確認する。

### G-1. 会社法上の手続き → [law-notes.md](law-notes.md#7-会社法平成-17-年法律第-86-号--利益相反取引)

| | チェック | これが無いと / あると |
|---|---|---|
| ⚠️ | **両社に兼任の取締役がいる**(代表でなくても) | 会社法 356 条 1 項 2 号の**直接取引**にあたる。「自己又は**第三者のために**株式会社と取引」の類型 |
| ❓ | **両社それぞれで承認**を取ったか | 片方だけでは足りない。A 社では B 社のため、B 社では A 社のための取引になる |
| ❓ | 承認機関は正しいか | **取締役会設置会社なら取締役会**(365 条 1 項)、**非設置会社なら株主総会**(356 条 1 項) |
| ❓ | **開示した「重要な事実」の中身**(相手方・取引内容・金額・期間・**価格の算定根拠**) | 開示が薄いと承認の効力が争われる。議事録に何を開示したか書く |
| ❓ | 継続的取引の**包括承認**を取っているか | 取引ごとの承認が原則。基本契約締結時に、種類・数量・金額・期間を開示して包括承認する実務がある |
| ❓ | 取締役会設置会社で、**取引後の報告**をしたか | 365 条 2 項の義務。遅滞なく取締役会へ報告 |
| ⚠️ | 承認を飛ばしている | 356 条 2 項が働かず**民法 108 条で無権代理**と構成されうる。加えて **423 条 3 項で任務懈怠が推定**され、損害が出たとき取締役個人が責任を負いやすい |
| — | 「自己のため」か「第三者のため」か | 他社の代表として行う取引は「第三者のため」。**428 条の無過失責任は及ばない**が、423 条 3 項の推定は及ぶ |

### G-2. 取引価格 → [law-notes.md](law-notes.md#8-法人税法昭和-40-年法律第-34-号--関係会社間の取引価格)

|---|---|---|
| ⚠️ | **時価(第三者間価格)から乖離していないか** | 安すぎれば提供側で**寄附金認定**(法人税法 37 条 8 項)、高すぎれば発注側から受注側への利益移転。**どちらにも振れる** |
| ❓ | **価格の根拠資料**(他社向け見積・実績単価・原価計算・稼働記録) | 「グループだから」で決めた形跡が残ると否認されやすい |
| ⚠️ | 同族会社に該当するか | 該当すれば**法人税法 132 条(行為計算否認)**の射程 |
| ❓ | 税理士に通したか | **税務は弁護士でなく税理士の領域。**価格設定と申告の実務は必ず顧問税理士に通す |

## 全類型に共通する「不在」の拾い方

**❓(不在)は、条文を読んでいるだけでは絶対に見つからない。** 以下を最後に必ず 1 周する。

1. **お金が入ってこないシナリオを 3 つ考える** — 検収が終わらない / 支払期日が来ない / 途中で解約される。**それぞれに対応する条項があるか**
2. **相手が悪意なく怠慢なだけのシナリオを考える** — 担当者が忙しくて放置したとき、契約はどう動くか。**みなし規定が無いと何も動かない**
3. **自分が抜けたいシナリオを考える** — 条件が悪化した / 相手と合わなかった。**抜ける手段があるか**
4. **相手が倒産するシナリオを考える** — 仕掛かり分は回収できるか。**期限の利益喪失・解除事由**があるか
5. **3 年後に見返すシナリオを考える** — この契約はまだ有効か。自動更新は。競業避止は解けたか。**契約レビューの成果物に「◯年◯月◯日までに判断」と日付を書く**

## 育て方

**実際に見た契約書で「このリストに無かった論点」に出会ったら、必ず追記する。** 追記のときは:

- **どの類型のリストに入れるか**を先に決める(全類型共通なのか、請負型だけなのか)
- **「これが無いと / あるとどうなるか」を必ず書く。** チェック項目だけ増やすとリストが機能しなくなる
- **✅ / ⚠️ / ❓ のどれか**を付ける。特に ❓(不在が問題)は意識して増やす
- 条文レベルの修正案が要るものは [clauses.md](clauses.md) に項を立て、ここからリンクする
- 法令に触れるものは、**先に [law-notes.md](law-notes.md) で裏取りしてから**書く
