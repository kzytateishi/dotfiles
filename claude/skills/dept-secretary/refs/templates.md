# 定型文書・定型連絡の文例集

そのまま使える文例。**`【】` は変数**であり、実データに置き換えて初めて完成する。

> **`【】` が 1 つでも残っている文面を「完成」として出さない。** 埋められない `【】` があるなら、それは**確認事項**であって下書きの不備ではない。「ここが埋まらないので確認してください」と明示して渡す。

> **送信・発行・支払い・予約は、必ず確認を取ってから。** このファイルの成果物は**下書きまで**。文面ができたことと、送ってよいことは別。

## 全文例に共通する 3 原則

1. **金額・日付・宛名・口座は推測で埋めない。** この 4 つは間違えると事故になる。一次ソース（Notion / Drive / 過去の同種書類）から取るか、確認事項として空ける
2. **過去の同種書類があればフォーマットを揃える。** 相手は前回と同じ形を期待している。**このファイルの型より、その取引先の前例が優先**
3. **相手の呼称を混ぜない。** 「様」「御中」「さん」を 1 通の中で揺らさない。会社宛は「御中」、個人宛は「様」、社内は既存の慣習に合わせる

## 件名の付け方

**件名だけで「誰から / 何の / どうしてほしい」が分かること。** 相手は件名でしか優先度を判断しない。

| 用途 | 型 |
|---|---|
| 送付 | `【送付】◯月分ご請求書の送付（【自社名】）` |
| 依頼 | `【ご確認依頼】【案件名】お見積の件（〜【日付】）` |
| 催促 | `【再送】【案件名】の件` — 1 回目は「再送」、督促と書くのは最終段階 |
| 日程 | `【日程調整】【用件】のお打ち合わせ` |
| 期限付き | 件名末尾に `（〜【日付】）` を付ける。本文だけに書くと読まれない |

## 請求書

### 記載事項（適格請求書 / インボイス）

適格請求書には、次の事項が記載されていることが必要（消法57の4①）。国税庁「消費税の仕入税額控除制度における適格請求書等保存方式に関する Q&A」問 54 より。

1. **適格請求書発行事業者の氏名又は名称及び登録番号**
2. **課税資産の譲渡等を行った年月日**
3. **課税資産の譲渡等に係る資産又は役務の内容**（軽減対象課税資産の譲渡等である場合には、資産の内容及び軽減対象課税資産の譲渡等である旨）
4. **課税資産の譲渡等の税抜価額又は税込価額を税率ごとに区分して合計した金額及び適用税率**
5. **税率ごとに区分した消費税額等**
6. **書類の交付を受ける事業者の氏名又は名称**

出典: <https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/01-09.pdf>（問 54、令和 6 年 4 月改訂）

あわせて確認済みの実務ポイント:

| 論点 | 内容 | 出典 |
|---|---|---|
| **消費税額の端数処理** | 1 円未満の端数が生じる場合、**一の適格請求書につき、税率ごとに 1 回**の端数処理を行う。切上げ・切捨て・四捨五入など**方法は任意**。**個々の商品ごとに端数処理してその合計額を記載することは認められない** | [問 57](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf) |
| **屋号での記載** | 電話番号を記載するなどして**交付する事業者を特定できれば**、屋号や省略した名称の記載でも差し支えない | 同 Q&A 問 55 |
| **登録番号の確認** | 「国税庁インボイス制度適格請求書発行事業者公表サイト」で、登録番号（T を除いた 13 桁の数字）から登録の有無を確認できる | <https://www.invoice-kohyo.nta.go.jp/> |
| **振込手数料を売上値引きにした場合** | 売上げに係る対価の返還等に係る**税込価額が 1 万円未満**であれば、適格返還請求書の交付義務は免除される。判定は**請求や債権の単位ごとの減額金額**による（例: 500,000 円の請求に対し振込手数料相当額 440 円を減額 → 免除される） | [問 28](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/28.pdf) |

> **⚠️ 上の免除が効くのは「売上値引きとして処理した場合」だけ。** 国税庁は振込手数料相当額の扱いを **3 通り**に分け、「**取引当事者間の契約関係等により対応が分けられる**」としている（問 29）。
>
> | 処理 | 必要なこと |
> |---|---|
> | ① **売上値引き**とする | 1 万円未満なら適格返還請求書の交付義務が免除（＝上の行） |
> | ② **代金決済上の役務提供の対価**とする | 売手は仕入税額控除のため、**買手から交付を受けた適格請求書（または仕入明細書等）の保存が必要** |
> | ③ 買手が売手のために**立替払**したものとする | 金融機関の適格請求書 + **立替金精算書等**の交付を受ける必要 |
>
> **どれに当たるかは契約次第で、②③は保存義務が生じる。**「振込手数料は 1 万円未満だから何もしなくてよい」と一般化しない。自分がどの処理をしているか分からなければ**税理士に確認する**。

> **上記以外の税務の判断はこのスキルではしない。** 源泉徴収の要否、消費税の課税・免税の判定、書類の保存方法（電子取引の保存を含む）、支払期日に関する法令上の制約などは、**税理士 / 専門家に確認する**。ここに書いていないことは「確認していない」という意味であって、「不要」という意味ではない。

### 送る前に必ず確認すること

- [ ] **宛名の正式名称**（「(株)」と「株式会社」、前株・後株、旧社名でないか）。**御中 / 様の使い分け**
- [ ] **金額**。税抜か税込かを取り違えていないか。**発注書・見積書の金額と一致するか**
- [ ] **対象期間**。前月分か当月分か。前回請求と重複・欠落がないか
- [ ] **お支払期限**。契約書の支払条件（締め日・支払サイト）と一致するか。**推測で「翌月末」と書かない**
- [ ] **登録番号**が正しいか（自社分）
- [ ] **消費税の端数処理**が税率ごとに 1 回になっているか（商品ごとに処理していないか）
- [ ] **軽減税率の対象**が含まれる場合、その旨の記載があるか
- [ ] **振込手数料の負担**の記載が、契約・従来の運用と一致しているか
- [ ] **送付先**（担当者個人か、経理宛か、指定の請求書システムか）。**前回どこに送ったか**を確認する
- [ ] 発行・送付は**本人の確認を取ってから**

## 見積書

### 構成

| 項目 | 注意 |
|---|---|
| 宛先 | 正式名称 + 御中 / 様 |
| 発行日 | — |
| 見積番号 | 改訂時は**枝番**（`-02`）にして、どれが最新か分かるようにする |
| **有効期限** | **必ず入れる。** 無いと古い金額で発注される。原価や稼働が変わる案件ほど重要 |
| 件名 | 何に対する見積か |
| 明細 | **数量 × 単価 × 金額**。人月・人日なら**単位を明記** |
| **前提条件** | この見積が成立する前提（→ 下記） |
| **含まれないもの** | **最重要**。書いていないものは「含まれる」と読まれる |
| 納期 / 期間 | 着手日起算か、契約日起算かを明記 |
| 支払条件 | 一括 / 分割、締め支払サイト |
| 消費税 | 税抜・税込の別を明記 |

### 前提条件・含まれないものの書き方

**トラブルの大半はここの不在から起きる。** 一般論で埋めず、その案件で実際に揉めうるものを書く。

```
【前提条件】
・本見積は【YYYY年M月D日】時点の要件（【要件資料名 / 打ち合わせ日】）に基づきます
・【必要な環境・アカウント・データ】は御社にてご提供いただくことを前提としています
・レビュー・ご確認は【N】営業日以内にご返答いただくことを前提としています
・作業時間は【平日◯時〜◯時】を想定しています

【本見積に含まれないもの】
・【要件変更・追加要望への対応】
・【納品後の運用・保守】
・【第三者サービスの利用料・ライセンス費用】
・【デザイン制作 / インフラ構築 / データ移行】など、明細に無い作業一式
※ 上記が必要となった場合は、別途お見積いたします
```

### 送る前に必ず確認すること

- [ ] **単価と数量の根拠**。「だいたい」で作らない（→ [extraction.md](extraction.md#i-数字固有名詞が曖昧なまま流れるもの)）
- [ ] **税抜/税込**の表記が明細と合計で一致しているか
- [ ] **有効期限**が入っているか
- [ ] **含まれないもの**が書いてあるか。**書いていない = 含まれると読まれる**
- [ ] 前回同じ相手に出した見積と**単価が矛盾していないか**
- [ ] 金額が大きい・期間が長い・知財が絡むなら、**契約条件は dept-legal 側で確認**する

## 催促

**催促は 3 段階。いきなり 3 段目に行かない。** 温度を上げるのは、前の段が無視されたときだけ。

> **催促の前に必ず確認すること:** ① **本当に届いているか**（迷惑メール / 送付先違い / システム経由の要否）② **自分側にボールが戻っていないか**（相手は自分の返事を待っている可能性）③ **期限は本当に過ぎているか**（自分が推測で置いた期限で催促していないか → これは最悪の事故）

### 1 回目 — やわらかい確認（相手のミスを想定しない）

```
件名: 【再送】【案件名】の件

【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【M月D日】にお送りした【件名 / 書類名】について、
念のためご確認をお願いできればと存じます。

行き違いでしたら申し訳ございません。
また、社内でご確認中でしたら、その旨だけでもお知らせいただけますと助かります。

お忙しいところ恐れ入りますが、よろしくお願いいたします。
```

> **1 回目に期限を入れない。** 届いていない可能性がある段階で期限を切ると、こちらが高圧的に見える。

### 2 回目 — 状況を尋ねる（事実を並べる）

```
件名: 【ご確認のお願い】【案件名】の件

【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【件名 / 書類名】につきまして、下記のとおりご連絡しております。

  ・【M月D日】 【書類名】送付
  ・【M月D日】 再送

現時点でご返答をいただけておらず、
【後続の作業 / 着手日 / 納期】に影響が出る可能性がございます。

ご状況をお聞かせいただけますでしょうか。
ご担当が変更されている場合は、恐れ入りますがご転送いただけますと幸いです。

よろしくお願いいたします。
```

### 3 回目 — 期限を切る（事務的に、感情を入れない）

```
件名: 【要ご対応】【案件名】の件（〜【YYYY年M月D日】）

【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【件名 / 書類名】につきまして、【M月D日】より複数回ご連絡しておりますが、
ご返答をいただけておりません。

つきましては、【YYYY年M月D日】までにご回答をお願いいたします。

同日までにご連絡をいただけない場合は、
【後続作業の一時停止 / 納期の見直し / 別途ご相談】とさせていただきます。

ご事情がございましたら、その旨をお知らせいただければ調整いたします。
よろしくお願いいたします。
```

> **3 回目を出す前に本人の確認を取る。** 取引関係に影響する文面であり、事務の判断ではない。
>
> **書かないこと**: 責める表現（「まだですか」「何度も言っていますが」）、皮肉、感嘆符。**事実と期限だけ**の方が強い。
>
> **入金の督促**は取引関係・契約条項に直結するため、文面と送付の可否を必ず本人に確認する。法的な手段に触れる文面は**このスキルでは書かない**（dept-legal / 専門家の領分）。

### 社内向けの催促

```
【担当者名】さん

【件名】の件、【M月D日】までにお願いしていた分どうなっていますか?
【後続作業】が止まっているので、状況だけ教えてください。

厳しそうなら期限を引き直すので、その方が早ければ言ってください。
```

> 社内は**短く・具体的に・逃げ道を用意する**。長い丁寧文は社内では嫌味になる。

## 日程調整

### 候補日の出し方

| 原則 | 理由 |
|---|---|
| **3〜5 枠出す** | 少ないと再調整、多いと選ぶのが面倒になる |
| **日付だけでなく曜日を書く** | 誤読・誤認識を防ぐ |
| **時間帯は幅で出す**（`14:00〜18:00 のうち 1 時間`） | 相手が調整しやすい |
| **所要時間を明記** | 相手が予定を確保できる |
| **オンライン / 対面と場所を明記** | 移動時間の有無で回答が変わる |
| **候補日の有効期限を書く** | 保留されると自分の予定が塞がり続ける |
| **タイムゾーンを書く**（相手が国外なら） | JST を明記する |

### 依頼

```
件名: 【日程調整】【用件】のお打ち合わせ

【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【用件】につきまして、一度お打ち合わせの機会をいただけますでしょうか。

  所要時間: 【N】分程度
  形式:     【オンライン（【ツール名】）/ 御社にお伺い / 弊社】
  議題:     【話したいこと】

下記のうちご都合のよい日時をお知らせください（日本時間）。

  ・【M月D日（曜）】 【HH:MM】〜【HH:MM】
  ・【M月D日（曜）】 【HH:MM】〜【HH:MM】
  ・【M月D日（曜）】 【HH:MM】〜【HH:MM】

いずれもご都合が合わない場合は、
ご都合のよい日時を【2〜3 つ】お知らせいただけますと幸いです。

なお、上記候補は【M月D日】までのご返答で確保しております。

よろしくお願いいたします。
```

### 確定の連絡

```
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

下記にて確定いたしました。よろしくお願いいたします。

  日時: 【YYYY年M月D日（曜）】【HH:MM】〜【HH:MM】（日本時間）
  形式: 【オンライン / 場所】
  URL:  【会議URL】
  議題: 【話すこと】

【当日までにご用意いただきたいもの: 【 】】
```

### 変更・お詫び

```
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【M月D日】にお約束しておりました打ち合わせにつきまして、
【理由】のため、日程を変更させていただけないでしょうか。
直前のご連絡となり、誠に申し訳ございません。

改めて下記の候補をご提示いたします。

  ・【M月D日（曜）】 【HH:MM】〜
  ・【M月D日（曜）】 【HH:MM】〜

ご都合をお聞かせいただけますと幸いです。
```

### 送る前に必ず確認すること

- [ ] **候補日が自分のカレンダーと衝突していないか**（移動時間・前後の予定を含む）
- [ ] **曜日と日付が一致しているか**（最頻出のミス）
- [ ] 会議 URL が**その日時のものか**（使い回しの URL を貼っていないか）
- [ ] **予定を確定させる操作（カレンダー登録・会議室予約）は本人の確認を取ってから**

## お礼・挨拶

**具体的なことを 1 つ書く。** 「ありがとうございました」だけの文面は、送っていないのと同じ。

### 打ち合わせ後

```
件名: 本日はありがとうございました（【自社名】【氏名】）

【取引先名】
【担当者名】様
```

## 断り

**早く断るほど親切。** 迷っている時間そのものが相手の損害になる。

| 原則 | |
|---|---|
| **結論を先に書く** | 前置きが長い断りは、期待を持たせて落とす分だけ残酷 |
| **理由は 1 つだけ、簡潔に** | 理由を並べるほど言い訳に見え、反論の余地を与える |
| **謝りすぎない** | 断るのは正当な判断。過剰な謝罪は次の依頼を呼ぶ |
| **代替案は出せるときだけ** | 出せないのに「また今度」と書くと、次の期待が残る |
| **嘘の理由を書かない** | 後で矛盾する。「今回はお受けできない」で十分 |

### 依頼を断る

```
【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【依頼内容】につきまして、ご相談いただきありがとうございました。
検討いたしましたが、【理由: 稼働の都合 / 対応領域が異なる 等】により、
今回はお受けすることが難しい状況です。

せっかくお声がけいただいたにもかかわらず、申し訳ございません。

【代替案がある場合: 【時期 / 範囲 / 体制】であればご相談可能です。】

今後ともよろしくお願いいたします。
```

### 条件が合わないとき（交渉の余地を残す）

```
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【依頼内容】につきまして、ご提示の【条件: 予算 / 納期 / 範囲】では
お受けすることが難しい状況です。

一方、【変えられる条件】であれば対応可能です。

  ・【納期を M月D日まで】いただける場合
  ・【対応範囲を「〜」に限定】する場合

ご検討いただけますと幸いです。
```

> **断りの送信は必ず本人の確認を取る。** 取引の継続可否に関わる判断であり、事務の範囲を超える。

## リマインド

**催促と別物。** 催促は期限を過ぎたもの、リマインドは**期限が来る前**のもの。混同すると相手を不快にさせる。

### 社外（用件だけ、責めない）

```
件名: 【リマインド】【用件】（【M月D日】）

【取引先名】
【担当者名】様

お世話になっております。【自社名】の【氏名】です。

【M月D日】が期限となっております【用件】について、
念のためご連絡いたします。

  ・【用件】: 【M月D日（曜）】まで
  ・【必要なもの / 提出先】: 【 】

すでにご対応済みでしたら、行き違いご容赦ください。
よろしくお願いいたします。
```

### 社外（予定のリマインド／前日）

```
【担当者名】様

明日のお打ち合わせについて、念のためご連絡いたします。

  日時: 【YYYY年M月D日（曜）】【HH:MM】〜
  形式: 【オンライン / 場所】
  URL:  【会議URL】

お待ちしております。よろしくお願いいたします。
```

### 社内（短く、事務的に）

```
リマインドです。

・【用件】 期限【M月D日】 担当【氏名】
・【用件】 期限【M月D日】 担当【氏名】

完了済みだったら教えてください。間に合わなそうなものがあれば先に言ってください。
```

### 自分向け（棚卸し）

```
■ 今週中に判断が必要なもの
・【契約名】自動更新 — 解約予告期限【M月D日】
・【サービス名】無料期間終了【M月D日】

■ 返事待ちで【N】日以上経過
・【相手】/【内容】/【M月D日】から
```

> **温度の目盛り**: 社内 = 短く事務的。社外 = 「念のため」「行き違いでしたら」を添える。**社外に社内の温度で送らない。社内に社外の温度で送らない**（後者は嫌味になる）。

## 送信前チェック（全文例共通）

- [ ] **`【】` が残っていないか**
- [ ] **宛名**（社名の正式表記 / 御中・様 / 担当者の氏名）
- [ ] **日付と曜日**が一致しているか
- [ ] **金額**の税抜・税込
- [ ] **添付**を付けたか。**添付ファイル名に前回の日付・別の取引先名が残っていないか**
- [ ] **宛先**（To / Cc / Bcc）。**複数社に一斉送信するときは Bcc**
- [ ] **前のスレッドに返信していないか**（別件の履歴が相手に見える）
- [ ] **署名**が正しいか
- [ ] **送信の可否を本人に確認したか**

## 育て方

実際に送った文面が固まったら、**このファイルの文例をその形に寄せる**（実データは `【】` に戻して書く）。

- 取引先ごとに書式が違うなら、**「その取引先の前例に合わせる」という運用**を守る。取引先固有のフォーマットをこのファイルに増やさない
- 制度の要件（記載事項・税率・期限）を追記・更新するときは、**必ず国税庁など公式情報を確認してから**書く。確認できないものは書かない
- 実データ（社名・取引先・口座・単価・住所）は**絶対にこのファイルに書かない**
