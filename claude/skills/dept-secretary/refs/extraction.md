# 取りこぼしの手口集

**落ちる仕事は「言われなかった仕事」ではなく、「言われたのに宿題の形をしていなかった仕事」。** 明示的な依頼は誰でも拾える。落ちるのは、**日本語の言い回しによって責任・期限・主語が溶けた**ものだけ。

このファイルは、その溶け方のパターン集。**ログを読むときは A〜J を順に当てる**。各パターンは「この表現が出てきたら → こう拾う」の形で書いてある。

> **拾うとは、宿題の形に戻すこと。** 「あとで見ときます」を「あとで見ときます」とメモしても拾ったことにならない。**何を / 誰が / いつまでに / 状態**の 4 つが埋まって初めて拾えたと言う（→ [必ず埋める 4 項目](#必ず埋める-4-項目)）。

---

## A. 期限が溶ける言い回し（最頻出）

「やる」とは言っているが、**いつまでかが無い**。放置すると永遠に来ない。

| この表現が出てきたら | こう拾う |
|---|---|
| 「あとで見ときます」「後ほど確認します」 | 期限なしの約束。**その場で期限を確定させるか、「期限なし」と明示して浮かせる**。黙って「今週中」にしない |
| 「今度やっておきます」「そのうち」 | 同上。「今度」は日付ではない |
| 「近いうちに」「早めに」「なるはやで」 | 発言者と受け手で想像している日付が違う。**両者の想定がズレている可能性ありとして確認事項に出す** |
| 「時間があるときに」「余裕ができたら」 | 事実上の無期限。優先度が低いなら**捨てるか、明示的に「保留」**に置く。ToDo に混ぜると腐る |
| 「来週あたり」「月末までには」 | 幅がある表現。**幅の遅い方の端**を仮の期限にし、仮であることを明記する |
| 「次回までに」 | **次回がいつか確定していない**のが本体の問題。「次回の日程が未定」を別の宿題として立てる |
| 「落ち着いたら」「一段落したら」 | 起点となるイベントが宿題。「何が終わったら着手か」を条件として書く |

> **「次回までに」は二重の宿題。** 作業そのものと、次回日程の確定。日程が決まらない限り作業の期限も決まらないので、**日程確定を先に立てる**。

## B. 主語が溶ける言い回し

「やる」ことは決まったが、**誰がやるかが無い**。全員が「誰かがやる」と思って誰もやらない。

| この表現が出てきたら | こう拾う |
|---|---|
| 「確認しておきます」 | **誰が / 誰に / 何を確認し / どこに返すのか**が全部抜けている。少なくとも「誰に返すのか」は確定させる |
| 「共有しておきます」 | 共有先が不明。**どこに（Slack のどのチャンネル / Notion のどのページ / メール）**を確定させる |
| 「対応します」「進めておきます」 | 対応の中身が未定義。**完了の見た目**（何が起きたら終わりか）を書く |
| 「やっておきましょう」（提案の形） | 提案であって割り当てではない。**担当未定**として立てる |
| 「こちらで巻き取ります」 | 「こちら」が個人か組織か不明。**組織なら中の誰かが未定**なので担当未定として扱う |
| 受動態全般（「〜される予定です」「〜が必要です」） | 主語が消えている典型。**能動態に書き直せなければ担当未定** |

> **担当を自分に寄せない。** 曖昧なものを全部自分の ToDo に入れると、自分のリストが他人の仕事で埋まって機能しなくなる。**「担当未定」と書いて浮かせる方が正しい**。

## C. 暫定が恒久化する言い回し

**その場では「仮」と全員が理解しているのに、記録には「決定」として残る。** 数か月後に誰も仮だったことを覚えていない。

| この表現が出てきたら | こう拾う |
|---|---|
| 「一旦これで」「ひとまずこの形で」 | **「いつ見直すか」が抜けた暫定合意**。見直しのトリガー（日付 or イベント）を宿題として立てる |
| 「とりあえず」「暫定で」 | 同上。記録には**必ず「暫定」と書く**。書かないと恒久化する |
| 「今回は特別に」「今回だけ」 | 前例になる。**「次回は元に戻す」を宿題**にしないと標準になる |
| 「仮で置いておきます」（数字・日程・文言） | 仮の値が下流にコピーされて一人歩きする。**仮の値がどこに複製されたか**を追う |
| 「動けばいいので雑でいいです」 | 後で直す前提の合意。**直す宿題**が立っていないなら立てる |
| 「あとで整理しましょう」 | 整理の担当と期限が無い C + A の複合 |

## D. 沈黙が承認になる言い回し

**返事をしないと合意したことになる**構造。放置すると、意図しない合意が成立する。

| この表現が出てきたら | こう拾う |
|---|---|
| 「問題なければ進めます」 | **沈黙 = 承認**。自分が受け手なら「いつまでに異議を出すか」を自分の期限として立てる。自分が送り手なら**期限を切って明示する**（「◯月◯日までにご連絡がなければ〜」） |
| 「特に反対がなければこの方向で」 | 同上。会議中に出たら**その場で「異議の締切」を確認**する |
| 「ご意見なければクローズします」 | クローズされると再提起のコストが上がる。**意見を出すか出さないかの判断**自体を宿題にする |
| 「認識合ってますか?」に誰も答えていない | **未回答が承認に見えている**。回答を宿題として立てる |
| 見積・契約書・仕様書を送って音沙汰なし | 承認とみなす期限が相手の頭にある可能性。**確認する** |

> **自分が「問題なければ進めます」と書く側のときは、必ず期限を入れる。** 期限のない同意要求は、相手にとっては永遠に判断を保留できるという意味になり、結局こちらが待たされる。

## E. 相手ボールになって消えるもの

自分の ToDo からは消えるが、**仕事は終わっていない**。ここが最も見えなくなる領域。

| この表現が出てきたら | こう拾う |
|---|---|
| 「〜さんに聞いてみます」 | 依頼した瞬間に**返事待ち**へ変わる。**いつまで待つか**（催促の日）を必ず決める。決めないと永久に待つ |
| 「先方に確認します」「持ち帰って検討します」 | 相手組織の中に入って見えなくなる。**次に接触する日**を決める |
| 「見積を依頼しました」「申請を出しました」 | 相手の処理を待っている状態。**通常どれくらいで返るか**を書き、超えたら催促 |
| 「返事待ちです」 | **いつから待っているか**を必ず記録する。日数が分からないと催促の判断ができない |
| 相手が持ち帰ったまま音沙汰がない | ログに**出てこない**ので言い回しでは拾えない。**過去の議事録を遡って「持ち帰り」を洗う**のが唯一の拾い方 |

> **返事待ちは ToDo に混ぜない。** 自分が動けないものが ToDo に並ぶと、リスト全体が「今日は何もできない」に見えて信用されなくなる。**別枠にして、待ち日数だけを見る。**

**返事待ちで見るのは 1 つだけ: 待ち日数。** 内容ではなく経過日数で催促を判断する（→ 催促の文面は [templates.md](templates.md#催促)）。

## F. 記録に残らない場所で決まるもの

議事録・チャットログを読んでも**そこに無い**。存在に気づくこと自体が仕事。

- **会議の終わりの雑談**で決まったこと。「あ、そういえば」「ちなみに」の後ろは議事録に載らない
- **会議前の 5 分の立ち話**、参加者が揃うまでの間に決まったこと
- **1on1・電話・DM** で決まった、他の人が知らないこと
- **画面共有中に口頭で決まったこと**（画面には残るが記録には残らない）
- **別スレッド・別チャンネル**で決まって、本流に反映されていないこと

> **拾い方は「記録の穴を疑う」。** 議事録の末尾が急に途切れている、決定事項の数が議論の量に比して少ない、といったときは**「他に決まったことはないか」を明示的に聞く**。推測で埋めない。

## G. 放置すると自動で確定するもの（不作為リスク）

**誰も何もしなくても期限が来て結果が確定する。** ToDo に載っていないので、意識的に棚卸ししないと拾えない。

| 種類 | 拾うポイント |
|---|---|
| **契約の自動更新** | 更新日ではなく**解約予告期限**（更新日の 1〜3 か月前など）が本当の期限。予告期限を宿題にする |
| **無料トライアル・無料期間の終了** | 終了日に自動課金される。**終了日の数日前**に判断の宿題を置く |
| **サブスク・SaaS の年額更新** | 更新月に自動で請求される。使っていないものを止めるなら更新前 |
| **ドメイン・SSL 証明書の更新** | 失効するとサービスが止まる。**自動更新が有効かどうか**まで確認しないと拾ったことにならない |
| **クレジットカードの有効期限切れ** | 決済が落ちて連鎖的にサービスが止まる |
| **見積・提案の有効期限** | 切れると再発行が必要になる |
| **申請・届出・更新の法定期限** | 遅れると不利益が確定する。**判断は本人 / 専門家に投げる**（このスキルは期限の存在を出すところまで） |
| **キャンペーン・割引の適用期限** | 過ぎると値上げが確定する |

> **これらは「やること」ではなく「やらないと決まってしまうこと」。** 通常の ToDo と混ぜず、**期限の近い順に別途出す**方が見落としにくい。

## H. 条件付き・保留のまま宙に浮くもの

| この表現が出てきたら | こう拾う |
|---|---|
| 「もし〜だったら対応します」 | **条件が満たされたかを誰も見ていない**。「条件の確認」自体を宿題にする |
| 「Aが決まってから着手します」 | A が宿題として立っていないと永久に着手されない。**A を先に立てる** |
| 「保留」「ペンディング」 | **解除の条件と、解除を判断する日**が無いと、保留のまま消える |
| 「必要になったらやります」 | 必要かどうかを誰も判断していない。**判断のタイミング**を決める |
| 「様子を見ましょう」 | いつ、何を見て、どう判断するかが無い。**見る日**を決める |

## I. 数字・固有名詞が曖昧なまま流れるもの

事務の失敗はここから起きる。**曖昧なまま書類に転記されると、間違いが確定する。**

| この表現が出てきたら | こう拾う |
|---|---|
| 「例の件」「あの案件」「いつもの」 | 何を指すか特定できないなら**特定を宿題にする**。推測で名前を埋めない |
| 「だいたい◯万円くらい」 | 見積・請求に使ってはいけない。**確定金額の確認**を宿題にする |
| 「月末」「月初」「来月アタマ」 | 人によって指す日が違う。**日付に変換して確認**する |
| 「◯◯さん」（同姓が複数いる / 社名が曖昧） | 宛名を間違えると事故になる。**フルネーム・正式社名を確認**する |
| 「税抜/税込」が明示されていない金額 | **どちらか確認するまで書類に書かない**（→ [templates.md](templates.md#請求書)） |

## J. チャット特有の消え方

- **スタンプ・絵文字だけの反応**が「了解」なのか「読んだ」なのか判別できない → 明示的な返答が必要なら宿題にする
- **長いスレッドの末尾**で決まったことが、親メッセージを見ている人に伝わっていない
- **編集された過去メッセージ**（決定内容が書き換わっている）
- **複数人が同時に返信**して、誰の案が採用されたか不明のまま流れた
- **「あとで返信します」と言ったまま**の未返信

## 抽出の手順

**3 周する。** 1 周目で拾えるのは明示的な依頼だけで、それは元々落ちない種類の仕事。

1. **1 周目 — 明示**: 「〜してください」「〜をお願いします」「ToDo:」など、依頼の形をしているものを拾う
2. **2 周目 — 言い回し**: A〜J を順に当てる。**カテゴリごとに「該当なし」を確認する**（流し読みしない）
3. **3 周目 — 不在**: 「決まっているべきなのに決まっていないこと」を探す。次回日程・担当・承認者・予算・期限。**F と G はここでしか拾えない**

> **拾えた数を成果としない。** ノイズを積んだリストは読まれなくなり、結果として全部落ちる。**判断がつかないものは「拾いきれなかったもの」に出す**（捨てない・水増ししない）。

### 拾う対象にしないもの

- **感想・雑談・愚痴**（行動が伴わないもの）
- **すでに完了している行動の報告**
- **一般論としての改善案**（「いつか整理したいね」レベルで、誰も約束していないもの）
- **自分が推測で作り出したタスク**。ログに根拠が無いものは**タスクではなく「確認したいこと」**として出す

## 必ず埋める 4 項目

拾った 1 件ごとに、以下を埋める。**埋まらない欄は空欄にせず、埋まらないと書く。**

### 何を

- **完了の見た目**で書く。「請求書の件」ではなく「【取引先】に◯月分の請求書を送る」
- 動詞で終える。名詞止めは状態が分からなくなる
- 1 件 1 行動。「確認して修正して共有する」は 3 件に割る

### 誰が

| 状況 | 書き方 |
|---|---|
| 明言された | その人を書く |
| 「こちらで」など組織単位 | 組織名 +「担当未定」 |
| 提案の形で終わった | **担当未定** |
| 自分だと思うが明言されていない | **「自分（要確認）」** — 勝手に確定させない |

### いつまでに

| 状況 | 書き方 |
|---|---|
| 日付が明言された | その日付 |
| 「来週中」など幅がある | **幅の遅い端 +「（発言ママ:「来週中」）」** |
| 何も言われていない | **「期限なし」** |
| 他のイベント待ち | **「【イベント】の後」** + そのイベントの日付が未定なら別途宿題化 |
| 自動確定系（G） | **予告期限 / 判断期限**（更新日そのものではない） |

### 状態

**未着手 / 進行中 / 返事待ち / 保留 / 完了** の 5 つ。

- **返事待ち**には必ず「誰の返事を / いつから待っているか」を添える
- **保留**には必ず「解除の条件 or 見直す日」を添える。無いなら保留ではなく**期限なしの未着手**
- **完了は自分で判断しない。** 本人が完了と言ったものだけ完了にする

## 期限を推測で埋めてはいけない理由

**推測した期限は、記録に載った瞬間に「約束された期限」として一人歩きする。** 誰も約束していない締切が生まれ、しかもそれを疑う人がいなくなる。

具体的に何が起きるか:

1. **相手を不当に遅延扱いする。** 「あとで送ります」を勝手に「今週金曜」と書くと、翌週に送られてきたときリストは「遅延」と表示する。相手は何も破っていないのに、催促が飛び、関係が悪くなる
2. **本当の期限が隠れる。** 推測の期限が入っていると「期限は決まっている」ように見えるため、**期限を確定させるという本来やるべき仕事が消える**。これが最も損害が大きい
3. **嘘の優先順位が生まれる。** 推測で「今週」と置いたタスクが、本当に今週締切のタスクと同じ行に並ぶ。**本物の締切が薄まる**
4. **転記されて出典が消える。** リストが Notion に写り、別の資料に写るうちに「誰がいつ決めたか」が失われ、根拠のない日付が既成事実になる

### 正しい扱い

| やってはいけない | 正しい |
|---|---|
| 「あとで見ときます」→ 期限: 今週中 | 期限: **期限なし** / 確認事項:「いつまでに見るか未確定」 |
| 「来週あたり」→ 期限: 月曜 | 期限: **来週金曜（発言ママ:「来週あたり」）** |
| 「月末まで」→ 期限: 31 日 | 期限: **月末（発言ママ）** / 確認事項:「月末が営業日ベースか要確認」 |
| 「急ぎで」→ 期限: 明日 | 期限: **未確定（「急ぎ」とのみ）** — 急ぎの度合いは本人に聞く |

> **期限が無いことは、悪い状態ではあっても間違いではない。** 悪い状態を悪い状態のまま見せるのが仕事であって、**見た目を整えるために嘘の日付を入れるのは仕事の失敗**。

## 育て方

実際に落ちた仕事が出たら、**なぜ拾えなかったか**を分類してこのファイルに還元する。

- 既存カテゴリの言い回しで拾えたはず → **その行の例に追加**（表現のバリエーション不足）
- どのカテゴリにも当たらなかった → **新カテゴリを追加**（構造として新しい溶け方）
- 拾えていたが優先度を誤った → extraction ではなく**並べ方の問題**。SKILL.md 側に還元する

誤検知が多いパターン（拾ったが実際は何もしなくてよかった）が続いた場合は、その行に**「拾わなくてよい条件」を併記**する。ノイズを減らすのも精度のうち。
